# 参照表声明缺少「按常量值过滤行」能力，同文件多子集无法隔离

## 现象

当一个参照表文件里**混了多类配置**（用某列的常量值区分），决策表想声明多个输入名各只取其中一类时，rule-sheet 无法表达「只匹配 `配置类别=某某` 的行」。两个输入名共用同一文件会读到**全部行**，存在交叉误匹配风险。

## 业务场景

pos-change-analysis 项目 03-tag-keypos 步骤有一张混合清单 `reference/03-销服岗位群-职能部门-清单.xlsx`：

| 配置类别 | 配置项 | 配置描述 |
|---|---|---|
| 销服岗位群 | EBG-军团长/系统部长 | ... |
| 销服岗位群 | EBG-企业销售副部长群（代表处） | ... |
| ... (136 行) | | |
| 职能部门 | 公司财经委员会 | ... |
| 职能部门 | 集团财经管理部 | ... |
| ... (38 行) | | |

共 175 行，`配置类别` 列有两种值：`销服岗位群`(136) / `职能部门`(38)。

决策表想声明两个输入名，**共用这一个文件**，但各只匹配一类：

| 输入名 | 期望只读的行 | 匹配键 |
|---|---|---|
| `职能部门` | `配置类别=职能部门` 的 38 行 | `配置项 = 本期.一层组织` |
| `销服群` | `配置类别=销服岗位群` 的 136 行 | `配置项 = 本期.岗位群-岗位与任职者信息报表` |

规则里用 `<输入名>.存在 == 是` 判断主表某行是否属于该类配置。

## 当前限制（源码证据）

1. **`InputSpec`（model.py:111-128）** 字段只有 `keys`(列对列匹配)、`dup_policy`、`append`、`sort`/`sep`/`placeholder`/`numbered`，**没有「按常量值过滤行」的字段**。
2. **`_parse_keys`（loaders.py:106-125）** 匹配键格式 `mine = theirs`（参照表列 = 主表列），只支持列对列，**不支持 `配置类别 = "职能部门"` 这种常量等值**。
3. **`_prepare_lookup`（engine.py:138-175）** 合并前只做：校验键列、剔键为空行、算派生变量、按重复键去重。**没有按常量过滤行的步骤**。

## 当前的实际行为（潜在 bug）

`职能部门` 和 `销服群` 两个输入都读同一文件的**全部 175 行**，只按 `配置项` 列匹配，**不按 `配置类别` 过滤**：

- `职能部门.存在 == 是` 会在主表 `一层组织` 命中**销服岗位群的配置项**时也变 `是`（136 行里若有与某 `一层组织` 同名的项）
- `销服群.存在 == 是` 会在主表 `岗位群-...` 命中**职能部门的配置项**时也变 `是`（38 行里若有与某 `岗位群` 同名的项）

两个输入的 `配置类别` 隔离失效。若业务上 `配置项` 的值在两类里恰好不重叠，bug 暂不暴露；一旦有重叠项就会误标。

消费代码（`pos-change-analysis/.cac/skills/pos-change-loop/scripts/tag_keypos.py:199-213`）：

```python
rs_run(
    rules_path=str(rules_path),
    base_dir=str(batch_dir),
    inputs={
        "本期": str(prepared_file),
        "职能部门": str(config_file),   # 同一文件
        "销服群": str(config_file),      # 同一文件
        ...
    },
    output=str(dst_file),
    ignore_tests=True,
)
```

## 期望

支持在输入声明里**按常量值过滤参照表行**，让多个输入名共用同一文件时各只取一个子集。

### 方案设想 A：输入 sheet 增加「筛选」列

「输入」sheet 增加一列「筛选」，写 `列名 = 常量值`（或 `列名 in (值1, 值2)`），`_prepare_lookup` 在合并前按它过滤行：

| 名称 | 匹配 | 重复键 | 筛选 | 说明 |
|---|---|---|---|---|
| 职能部门 | 配置项 = 本期.一层组织 | 取第一条 | 配置类别 = 职能部门 | ... |
| 销服群 | 配置项 = 本期.岗位群-岗位与任职者信息报表 | 取第一条 | 配置类别 = 销服岗位群 | ... |

- `InputSpec` 新增 `filters: list[tuple[str, str]]` 字段（列名, 常量值）
- `_prepare_lookup` 在「剔键为空行」之前先按 filters 过滤
- YAML 输入声明对应增加 `筛选:` 键

### 方案设想 B：匹配键支持常量等值

`_parse_keys` 里 `mine = theirs` 的 `theirs` 如果是字面量（非 `主表.列名` 形式），当作常量等值过滤：

```
匹配: 配置项 = 本期.一层组织, 配置类别 = "职能部门"
```

但这种写法把「过滤」和「对齐」混在匹配键里，语义不够清晰，且 `配置类别 = 职能部门` 看起来像「主表有 `职能部门` 列」会混淆。

**倾向方案 A**，语义清晰，与现有 `匹配`/`重复键`/`独有行` 并列。

## 复现步骤

1. 准备一个混合清单 `mixed.xlsx`，`类别` 列有 A/B 两值，`名称` 列有部分同名项跨类重叠
2. 决策表声明两个输入各绑同一文件：
   - 输入1 `类A`：匹配 `名称 = 本期.x`
   - 输入2 `类B`：匹配 `名称 = 本期.y`
3. 规则：`类A.存在 == 是` 时输出 `标签=A`；`类B.存在 == 是` 时输出 `标签=B`
4. 主表某行 `x` 恰好等于 `类B` 里的某个 `名称` → `类A.存在` 误为 `是` → 标签误标 A

## 备注

- 当前 workaround 是把混合清单**拆成两个文件**（03-销服岗位群-清单.xlsx / 03-职能部门-清单.xlsx），决策表两个输入各绑一个文件。但这破坏了业务方「一张清单管两类配置」的原有维护方式，且文件数翻倍。
- 若 `配置项` 的值在两类里完全不重叠，bug 不会暴露；但这是数据巧合不是规则保证，新增配置项时随时可能引入重叠。
