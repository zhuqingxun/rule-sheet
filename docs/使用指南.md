# rule-sheet 使用指南

本文讲怎么用: 安装运行、规则文件的两种写法 (Excel 决策表 / YAML) 的精确格式、单元格与表达式语法、输出结果、Python API 和常见报错。为什么这样设计见 [设计架构.md](设计架构.md)。

## 1. 安装与命令

需要 [uv](https://docs.astral.sh/uv/)。在项目目录执行:

```powershell
uv sync
uv run rule-sheet run  examples/customer-sync/规则_决策表.xlsx   # Excel 决策表
uv run rule-sheet run  examples/customer-sync/rules.yaml         # 同一组规则的 YAML 版
uv run rule-sheet test examples/customer-sync/rules.yaml         # 只跑规则文件内嵌的测试用例
uv run rule-sheet run  examples/status-machine/rules.yaml -i 本期=本期岗位_2026-10.xlsx -i 上期=上期岗位_2026-09.xlsx -o 结果.xlsx
uv run rule-sheet run  examples/position-tags/规则_决策表.xlsx   # 多标签分类: 多条拼接 / 文本关键字 / 清单当参照表
uv run rule-sheet --version
```

`rule-sheet <规则文件>` 省略子命令等价于 `run`。

模型是 **规则文件 + 输入文件 → 输出文件**。规则文件声明有哪些输入 (名字、怎么对齐到主表), 是形参; 文件是实参, 两种给法: 规则文件里写默认文件 (任务文件夹模式, 见第 2 节), 或命令行 `-i 名称=路径` (每月换数据文件不用改规则)。两种可以混用, 命令行优先。

| 子命令 / 选项 | 作用 |
|---|---|
| `run <规则文件>` | 先跑内嵌测试, 全部通过才读入各输入表、执行规则、写出结果 |
| `run -i 名称=路径` | 绑定一个输入 (可重复)。名称是规则文件「输入」里声明的; 路径相对当前目录, 可带 `#sheet名` (不带则读第一个 sheet); 覆盖规则文件里的默认文件 |
| `run -o PATH` / `--output PATH` | 覆盖规则文件里的输出路径 |
| `run --base-dir DIR` | 规则文件内相对路径 (默认文件 / 输出) 的基准目录, 默认规则文件所在目录; 不影响 `-i` 给的路径 |
| `run --ignore-tests` | 内嵌测试有失败也继续处理真实数据 |
| `run --dry-run` | 只打印变更, 不写文件 |
| `test <规则文件>` | 只跑内嵌测试用例, 不读数据表 |
| `format <规则.xlsx> [-o 路径]` | 按版式规范 (3.6 节) 重排 Excel 规则工作簿: 颜色、列宽、换行、冻结。默认原地改写, `-o` 写到别处。先按加载器校验结构, 结构错就报错不碰文件 |

退出码: `0` 成功; `1` 测试未通过 (`run` 因此停止, 或 `test` 有失败); `2` 规则文件 / 数据有错 (打印 `错误: ...`)。

## 2. 任务目录约定

一个任务一个文件夹, 数据和规则文件放一起, 规则文件的「输入」里用相对路径写默认文件, 双击 / 不带参数运行即可:

```
customer-sync/
  客户客户.xlsx        主表, 被更新的表 (规则里叫 客户)
  本月流水.xlsx        参照表, 只读 (规则里叫 本月)
  规则_决策表.xlsx     规则 (Excel 写法)
  rules.yaml           规则 (YAML 写法, 可选)
  output/              结果输出 (不进 git)
```

数据每月换文件名、或者规则要复用到别的数据上时, 规则文件里不写默认文件 (或写了也行), 运行时 `-i 客户=客户主表_2026-10.xlsx -i 本月=流水_2026-10.xlsx` 绑定。

## 3. 规则文件: Excel 决策表写法

一个 `.xlsx`, 五张 sheet。sheet 名固定; `输入` 与 `决策表` 必须有, `设置`、`变量定义`、`测试` 可选。

### 3.1 输入与设置

「输入」sheet 声明规则有哪些输入: 第 1 行列名 (顺序随意), 之后一行一个输入。

| 列 | 必填 | 内容 |
|---|---|---|
| 名称 | 是 | 规则里引用这张表的列时用的前缀, 如 `客户` → `客户.状态`。不能重复 |
| 匹配 | 是 | **主表那一行写 `主表`** (输出的行就是它的行, 规则写回的是它的列; 只有一个输入时可留空)。其它输入写对齐到主表的键: 两边同名写 `岗位编码`, 不同名写 `工号 = 客户.拟任人工号` (本表的列 = 主表的列), 多个键逗号分隔 |
| 重复键 | 否 | 参照表里同一个键出现多行时: `取第一条` (默认) / `报错` |
| 文件 | 否 | 默认绑定的文件, 相对规则文件所在目录, 可带 `#sheet名`。不写则必须在命令行 `-i` 给 |
| 说明 | 否 | 不参与解析 |

| 名称 | 匹配 | 重复键 | 文件 |
|---|---|---|---|
| 客户 | 主表 | | 客户客户.xlsx |
| 本月 | 客户编号 | 取第一条 | 本月流水.xlsx |

参照表可以有任意多个, 各自对齐到主表 (星型); 没有参照表也行 (只按规则改一张表)。参照表键列为空的行不参与匹配; 内置变量 `<参照表名>.存在` 表示主表这一行在该参照表里是否匹配到。

「设置」sheet 可选: 第 1 行表头, 之后 A 列设置项、B 列值。

| 设置项 | 值 |
|---|---|
| 基准日期 | `天数差` 等计算用的「今天」; 不填取运行当天。固定下来可保证每次结果一致 |
| 输出 | 默认输出路径, 相对规则文件所在目录; 不填为 `output/<主表文件名>_更新后.xlsx`; 命令行 `-o` 可覆盖 |
| 拼接分隔符 | 命中策略 `多条拼接` 用的分隔符, 默认 `/`; 策略不是 `多条拼接` 时写了报错 (多半是策略名写错) |

**清单 / 白名单文件也是参照表**: 「本岗编码属于某清单」不需要新语法, 把清单文件声明成一个输入 (匹配 = 清单里的编码列, 对齐到主表), 条件写 `<清单名>.存在` = `是`。清单里多出来的行不影响, 同一份清单要对主表两列用 (本岗编码 / 拟任岗位编码) 就声明两次、起两个名字。多个清单放在一个工作簿里时用 `文件: 配置表.xlsx#职能部门`。样例 position-tags 的 `关键岗位清单` 就是这么写的。

0.4 以前的「匹配设置」sheet (左表 / 右表 / 左表别名 / 右表别名 / 匹配键 / 右表重复键) 仍能读, 自动折算成上面的声明; 对照表见 README「从 0.4 升级」。

### 3.2 变量定义 (可选)

第 1 行表头, 之后每行: A 列变量名、B 列表达式。A 或 B 为空的行忽略 (可以用来写备注)。按行顺序求值, 后面的可以引用前面的。

```
偏差率          abs(本月.金额 - 客户.金额) / 客户.金额
距上次活跃天数  天数差(基准日期, 客户.上次活跃)
```

表达式语法见第 5 节。

### 3.3 决策表

两行表头 (列类型行 + 列名行), 之前可以放元信息, 之后每行一条规则。**表头按内容识别**: 写着 `规则ID` 的第一行就是列类型行, 下一行是列名行, 不固定在第几行。

| 行 | 内容 |
|---|---|
| 元信息行 (可选, 任意行数) | 命中策略: 一格写 `命中策略`, 右边一格写策略名 `优先级` (默认) / `唯一` / `首次命中` / `多条拼接`, 写别的报错; 没有这一行取默认。其余格可写说明 |
| 列类型行 | 每列的类型: `规则ID` (恰好一列) / `优先级` (可选) / `输入` / `输出` / `说明` (可选)。拼错报错; 留空的列不参与解析 |
| 列名行 | 每列的名字: 输入列填变量名 (如 `客户.状态`、`偏差率`), 输出列填主表要写回的列名 (如 `状态`)。标了类型的列没写名字报错 |
| 正文 | 每行一条规则。`规则ID` 为空的行跳过; `优先级` 留空取 `1000 + 行序` (即排在所有写了优先级的规则之后, 按行序) |

输入格写单元格条件 (第 4 节), 输出格写要写回的值 (第 4.2 节)。同一行的各输入格之间是 AND。

**跨变量的「或」: 相邻几行写同一个规则 ID**, 它们是同一条规则的几个分支, 每行内各格 AND、行间 OR。优先级、输出、说明以首行为准, 续行只写条件 (优先级和输出格留空, 或与首行完全相同, 否则报错, 这样改了一行漏改另一行能被抓住)。规则 ID、优先级、输出格都可以合并单元格, 合并区域按左上格的值算。不相邻的重复 ID 报错。样例 status-machine 的 S3:

| 规则ID | 优先级 | 本期.类别-会议 | 上期.类别-会议 | 拟任人有变化 | 流程节点有变化 | 状态-会议 |
|---|---|---|---|---|---|---|
| S3 | 3 | - | = 本期.类别-会议 | 是 | - | 02-进展更新 |
| S3 | | - | = 本期.类别-会议 | - | 是 | |

等价于 YAML 的 `任一满足:`。分支多、或者「或」有业务含义时, 另一种写法是在「变量定义」里用 `或` 组合成一个派生变量 (如 `有变化: 拟任人有变化 或 流程节点有变化`), 决策表里只留一列。

以 `=` 开头的格 (`= 活跃`、`= 本期.类别-会议`、`=客户.金额 * 1.1`) 在 Excel 里输入时会被当成公式, 显示 `#NAME?`。rule-sheet 读的是格里的原文, 所以照样能用; 想让它显示正常, 先把单元格设成文本格式再输入, 或以 `'` 开头。规则工作簿里不要写真正的 Excel 公式, 读到的会是公式原文而不是计算结果。

### 3.4 测试 (可选)

与决策表同样的两行表头: 列类型行 (`用例` 恰好一列 / `输入` / `期望` / `说明`) 和列名行 (输入列填变量名, 期望列填输出列名), 按写着 `用例` 的行识别, 可以直接从第 1 行开始。之后每行一个用例, `用例` 为空的行跳过。

- 输入格直接写变量的值 (不是条件)。`<参照表名>.存在` 这一列写 `是` / `否`。留空或写 `空` = 该变量为空值。
- 决策表引用了、但用例没有这一列的变量, 一律视为空值。
- 期望格留空 = **该列不变**。有值 = 执行后该列应等于此值。写 `空` (或 `清空`、`为空`) = 执行后该列应为空值, 用来验证 `清空` 输出; 留空和 `空` 不一样, 前者抓「不该动的被动了」, 后者抓「该清的没清」。
- 派生变量 (变量定义里的) 可以直接在输入里给值, 给了就不再推导; 留空或没有这一列则按表达式推导 (推导用到的列也可以在输入里给), 推导失败置空。
- **列名在加载时校验**: 期望列必须是决策表的输出列; 输入列必须是规则引用到的变量 (表头输入列, 以及输入格右侧 `!= 上期.电话`、输出格 `=客户.金额 * 1.1` / `本月.电话` 里引用的)、派生变量或其表达式里引用的列、`<参照表名>.存在`、`基准日期`, 或 `<主表名>.<输出列>` (给输出列的原值)。对不上就报错, 因为拼错的期望列会被整列忽略、拼错的输入列填了不起作用, 用例会「假通过」。
- 有「测试」sheet 但一条用例都没有也报错; `rule-sheet test` 对没有用例的规则文件返回 1。

### 3.5 一张决策表长什么样

以自带样例为例 (颜色只是视觉提示, 解释器不读颜色):

| 规则ID | 优先级 | 客户.状态 | 偏差率 | 本月.存在 | 距上次活跃天数 | 本月.电话 | 状态 | 电话 | 复核标记 | 备注 |
|---|---|---|---|---|---|---|---|---|---|---|
| R1 | 1 | 活跃 | > 0.05 | 是 | - | - | - | - | 待复核 | 金额偏差超 5% |
| R2 | 2 | != 休眠 | - | 否 | > 180 | - | 休眠 | - | - | 连续 6 个月无流水 |
| R3 | 3 | - | - | 是 | - | != 客户.电话 | - | 本月.电话 | - | 电话变更 |

### 3.6 版式规范与 `rule-sheet format`

解释器不读颜色和列宽, 但一张好读的表对业务人员很重要。版式是一套固定规范, 定义在 `rule_sheet/style.py`: 样例生成脚本只写内容, 版式由它套; 业务人员在 Excel 里改乱了, `rule-sheet format 规则.xlsx` 一键恢复 (默认原地改写, 文件被 Excel 打开时报错而不是写副本)。

| 项目 | 规范 |
|---|---|
| 列类型配色 | 输入 浅蓝 `DDEBF7` / 输出 与 期望 浅绿 `E2EFDA` / 说明 浅黄 `FFF2CC` / 规则ID 优先级 用例 浅灰 `EDEDED` (只在表头)。表头与正文同色, 黄色 = 注释、不参与解析 |
| 键值 sheet (输入 / 设置 / 变量定义) | 第 1 行灰底 `D9D9D9` 加粗, A 列加粗, 「说明」列浅黄 |
| 字体 / 边框 / 对齐 | 表头加粗; 表区域细灰边框; 垂直居中; 输入 与 ID 类列水平居中, 输出 / 说明 左对齐 |
| 列宽 | 按内容算 (中文算 2 个字符宽, 另加 2 留白), 每类列有区间: 规则ID 8–12 / 优先级 8–10 / 用例 8–12 / 输入 10–28 / 输出 10–40 / 期望 10–28 / 说明 24–60; 键值 sheet 按列名: 名称 10–16 / 匹配 10–28 / 重复键 8–12 / 文件 14–36 / 设置项 12–16 / 值 16–40 / 变量 12–24 / 定义 24–60 / 说明 30–70 |
| 换行与行高 | 内容超过列宽上限的格换行 (不再加宽), 行高按估算的行数显式写入 (每行 15 磅), 各种查看器表现一致; 估算偏差时 `format` 重算 |
| 冻结 | 决策表 / 测试: 冻结到列名行之下、最左边连续 ID 类列 (规则ID / 优先级 / 用例) 之右; 其它 sheet 冻结首行 |
| 元信息行 (表头之上) | A 列和 `命中策略` 标签加粗, 其余有字的格浅黄, 不参与定宽 (长说明溢出到右边的空格里显示) |
| 单元格格式 | 以 `=` 开头的格存为文本 (否则 Excel 当公式显示 `#NAME?`); 日期格 `yyyy-mm-dd` |

`format` 用加载器同一套逻辑找表头, 所以它和解释器对「哪里是表头」永远一个答案。openpyxl 往返会保留批注、数据验证、条件格式, 但会丢图片和图表; 规则工作簿里一般没有这些。没标类型的列 (备注列) 不着色、不参与定宽。

## 4. 单元格语法

### 4.1 输入格 (条件)

| 写法 | 含义 |
|---|---|
| `-` 或留空 (也认 `—`、`任意`) | 不关心 |
| `活跃` | 等于。裸文字按文本比较; Excel 里设成数字 / 日期格式的格按数字 / 日期比较 |
| `"VIP 小幅偏差, 关注"` | 值本身含逗号时加引号 (单双引号都可), 否则会被当成枚举拆开 |
| `> 0.05` `>= 180` `< 1` `<= 1` | 比较 |
| `= 活跃` `== 活跃` | 等于 (显式写法) |
| `!= 休眠` `<> 休眠` | 不等于 |
| `!= 客户.电话` | 比较的右侧可以是另一个变量名 |
| `[0.02..0.05]` | 闭区间; `(` `)` 为开区间, 可混用如 `(0..1]` |
| `VIP, 金卡` | 枚举: 逗号分隔, 任一满足。每一项都可以是上面任何写法, 如 `> 10, 为空` |
| `= 空` / `!= 空` | 判空。`为空` / `非空` 是同义写法, 单独一个 `空` 等于 `= 空`。`空` 是关键字, 要匹配文字「空」加引号; `> 空`、`[空..5]` 报错 |
| `not(...)` | 取反。只对有值的格成立, 例外: `not(空)` / `not(为空)` / `not(非空)` 是纯否定 |
| `包含 CEO, 总裁` / `不包含 助理` | 子串匹配, 按字面 (不是正则), 逗号分隔的几项任一命中; 也可写 `包含(CEO, 总裁)`。项按原文取 (`开头是 01` 的 01 不会变成数字), 恰好是变量名的换成那一列 (`包含 本期.姓名`), 要当文字就加引号。空值不成立, `不包含` 对空值也不成立 (有值且一个都不含才成立) |
| `开头是 2-, 3-` / `开头不是 11-` / `结尾是 部` / `结尾不是 部` | 前缀 / 后缀匹配, 规则同上。关键字后面要有空格或括号, 单元格值恰好是「包含测试」这样的文字时仍按普通文字比较 |
| `是` / `否` | 仅当被比较的列是布尔列 (如 `本月.存在`) 时转成真 / 假 (也认 `true` / `false` / `yes` / `no`); 文本列里就是文字 |
| `2026-10-19` | 日期字面量 |

**空值规则**: 空值参与任何比较 (等于、不等、大小、区间、枚举) 都不成立。要判空必须显式写 `= 空` / `!= 空` (或 `为空` / `非空`); 枚举里也可以放 `空`: `活跃, 空` = 活跃或为空。`= 空` 是唯一把「空」当成可比对象的写法, `= 客户.电话` 在两边都为空时仍不成立。

### 4.2 输出格

| 写法 | 含义 |
|---|---|
| `-` 或留空 | 不改 |
| `待复核` | 写入这个字面值 (Excel 里的数字 / 日期格原样写入) |
| `"本月.电话"` | 加引号表示强制当文字, 即使它长得像变量名 |
| `本月.电话` | 恰好是一个变量名时, 复制该变量的值 |
| `=客户.金额 * 1.1` | 以 `=` 开头是表达式, 按第 5 节求值。「条件 A 时写 X 否则写 Y」用 `=如果(上期.x != 空, 上期.x, 基准日期)`, 拼文本用 `=拼接(本期.姓名, "(", 本期.工号, ")")` |
| `清空` (也认 `置空`、`空`、`=空`) | 把该列写成空值。和 `-` 不同: `-` 是不碰这一列, `清空` 是主动清掉 (变更明细显示 `旧值 -> 空`)。要写文字「清空」/「空」就加引号 |

## 5. 表达式语法 (变量定义、`=` 输出格、YAML 条件)

表达式是 Python 语义, 对整列向量化求值。可以写:

- 变量: `<输入名>.<列名>` (输入名是「输入」里声明的, 如 `客户.状态`、`本月.金额`)、`<参照表名>.存在` (该参照表是否匹配到, 布尔)、`基准日期`、变量定义里的名字
- 列名含 `-`、`/`、全角括号的直接写: `本期.类别-会议 == "变动通报"`、`非空(本期.岗动-拟任命人-流程节点)`。`-` 后面紧跟 `别名.`、数字或已知名字时才是减号 (`本期.金额-上期.金额`、`本期.金额-1`、`本期.金额-偏差率`); 写减法时两边加空格最稳妥。反过来, 列名里 `-` 后面恰好是数字的 (如 `类别-2024`) 会被当成减法, 这种列名用下一条的反引号
- 列名含其它符号 (半角括号、空格、`%` 等) 的用反引号包裹整个名字: `` `本期.金额(万元)` > 100 ``。反引号里的名字必须在命名空间里, 否则报错。**YAML 里以反引号开头的表达式整行要加引号** (`` - "`本期.金额(万元)` > 100" ``), 否则 YAML 本身就解析不了; Excel 单元格不受影响
- 运算: `+ - * /`、比较 `== != > >= < <=` (可以链式: `0.02 <= 偏差率 <= 0.05`)、`in` / `not in` (`客户.等级 in ("VIP", "金卡")`)、括号
- 时长字面量 `N天` (可带小数): `本期.推荐时间 >= 基准日期 - 365天`、`基准日期 + 30天`。只有「天」, 月 / 年长度不固定不提供
- 连接词: `且` / `或` / `非` (也认 `and` / `or` / `not`), 两侧留空格, 按行逐元素运算: `非空(本期.拟任人) 且 本期.拟任人 != 上期.拟任人`
- **空值**: 所有比较任一侧为空都不成立, 与单元格一致 (`本月.电话 != 客户.电话` 在任一方为空时为假, 不会把空值当成「不同」)。判空写 `x == 空` / `x != 空` (`为空(x)` / `非空(x)` 同义); `空` 也可以放进 `属于(x, "a", 空)` / `x in ("a", 空)` 的枚举里。`空` 是关键字不是值: 只能和 `==` / `!=` 搭配, `x > 空`、`空 + 1`、`abs(空)` 报错; 两个变量都为空时 `x == y` 仍不成立。`非` / `不满足:` 是纯逻辑取反, 空值行也为真, 要排除空值自己加 `x != 空`
- 字面量: 数字、`"字符串"` (必须加引号)、`是` / `否` / `true` / `false`
- 函数:

| 函数 | 含义 |
|---|---|
| `abs(x)` `round(x, n)` | Python 内置, 对整列逐行生效 |
| `min(...)` `max(...)` | Python 内置, 只适合标量参数 (如 `min(客户.金额, 100)` 这类对整列取小会报错) |
| `天数差(晚, 早)` / `days_between(晚, 早)` | 两个日期相差的天数 |
| `非空(x)` / `为空(x)` | 判空, 返回布尔; 与 `x != 空` / `x == 空` 同义 |
| `属于(x, 值1, 值2, ...)` | x 等于任一个值 |
| `包含(x, 文本1, 文本2, ...)` / `不包含(...)` | x 含任一子串 / x 有值且一个都不含。按字面匹配, 不是正则 (`.`、`+` 就是字符本身); 非文本列先转成文本 (7.0 按 `7`, 日期按 `2026-10-01`); 文本参数也可以是列 |
| `开头是(...)` / `开头不是(...)` / `结尾是(...)` / `结尾不是(...)` | 前缀 / 后缀匹配, 规则同上 |
| `拼接(a, b, ...)` | 连成一个文本。空值当空串 (`拼接(x, "元")` 在 x 为空时是 `元`), 所有参数都为空时结果是空值; 数字 7.0 写成 `7`, 日期写成 `2026-10-01`, 布尔写成 是 / 否 |
| `数字(x)` | 文本里的第一个数: `22级` / `P23` / `第3档` → 22 / 23 / 3, 取不到为空; 数值原样返回。Python 的 `float()` / `int()` 不开放, 用它 |
| `如果(条件, 真值, 假值)` | 向量化三元: 条件为真取真值, 否则取假值 (条件为空算假)。分支可以是列、字面量或 `空`, 可以嵌套 |

文本函数、`拼接`、`数字` 的参数不能是 `空` (报错), 想把空值当空串拼接直接传列。

**几条规矩**:

- 字符串必须加引号: `客户.状态 == "活跃"`; 裸的 `活跃` 会被当成变量名
- 布尔列写 `本月.存在 == 是` / `== 否`, 或直接写 `本月.存在` / `非 本月.存在`
- 一个派生变量就是一个布尔列时, 条件里直接写它的名字 (`拟任人有变化`), 不用 `== 是`
- 三元写 `如果(条件, 真值, 假值)`; Python 的 `x if 条件 else y` 和对整列做 `bool()` 报「对整列做了真假判断」
- 中文连接词两侧留空格 (`a 且 b`); 紧贴着写 (`a且b`) 会被当成一个名字

## 6. 规则文件: YAML 写法

```yaml
输入:                                  # 同 Excel「输入」sheet: 名字 -> {文件, 匹配, 重复键}
  客户: {文件: 客户客户.xlsx, 匹配: 主表}                     # 主表: 输出的行就是它的行
  本月: {文件: 本月流水.xlsx, 匹配: 客户编号, 重复键: 取第一条}  # 按 客户编号 对齐到主表; 重复键 可省
  # 花名册: {匹配: 工号 = 客户.拟任人工号}                    # 参照表可以有任意多个; 不写 文件 就得在命令行 -i 给

设置:                                  # 可省
  基准日期: 2026-10-19                  # 可省, 默认运行当天
  输出: output/客户主表_更新后.xlsx     # 可省, 默认 output/<主表文件名>_更新后.xlsx
  # 拼接分隔符: /                       # 只在 命中策略: 多条拼接 时用, 默认 /

变量:                                  # 可省; 有序, 后面的可引用前面的
  偏差率: abs(本月.金额 - 客户.金额) / 客户.金额
  距上次活跃天数: 天数差(基准日期, 客户.上次活跃)

命中策略: 优先级                        # 可省, 默认 优先级; 或 唯一 / 首次命中 / 多条拼接

规则:
  - 编号: R1                           # 可省, 默认 R1、R2…
    名称: 活跃客户金额偏差超 5% 需复核    # 可省, 只作说明
    优先级: 1                          # 可省, 默认 1000 + 序号
    当:                                # 条件树, 见下; 省略 = 无条件命中
      - 客户.状态 == "活跃"
      - 本月.存在 == 是
      - 偏差率 > 0.05
    则:                                # 输出列 -> 值, 值的写法同 Excel 输出格; 省略 = 命中但什么都不改
      复核标记: 待复核
      备注: 金额偏差超 5%
      提醒: 清空                       # 把该列写成空值; 不想碰的列直接不写 (裸 - 在 YAML 里是语法错误, 要写 "-")

  - 编号: R5
    优先级: 5
    当:
      - 本月.存在 == 是
      - 任一满足:                      # OR
          - 本月.电话 == 空              # 判空 (为空(本月.电话) 同义)
          - 客户.电话 == 空
    则:
      提醒: 电话有缺失

测试:                                  # 可省
  - 用例: T1 偏差 8% 触发 R1            # 可省, 默认 T1、T2…
    输入: {客户.状态: 活跃, 偏差率: 0.08, 本月.存在: 是}
    期望: {复核标记: 待复核, 备注: 金额偏差超 5%}
  - 用例: T2 偏差 3% 不动
    输入: {客户.状态: 活跃, 偏差率: 0.03, 本月.存在: 是}
    期望: {}                           # 空 = 什么都不变
```

**条件树** (`当:` 的内容):

| 写法 | 含义 |
|---|---|
| 一个字符串 | 一条表达式 |
| 列表 | 全部满足 (AND) |
| `全部满足: [...]` | AND, 显式写法 |
| `任一满足: [...]` | OR |
| `不满足: <子条件>` | NOT |

三者可以互相嵌套。`当:` 省略或为空 = 无条件命中所有行。`任一满足:` 对应决策表里的「多行同一个规则 ID」; 表达式内部也可以直接用 `且` / `或`, 两种写法任选。规则 `编号` 不能重复。

**YAML 的三个坑**:

- 花括号流式写法里值含逗号必须加引号: `期望: {备注: "VIP 小幅偏差, 关注"}`, 否则逗号后面会被当成另一个键。块式写法 (每行一个键) 不需要。
- 表达式里的字符串要加引号: `客户.状态 == "活跃"`; 但 `则:` 和 `测试:` 里的值是普通 YAML 值, 不加引号。
- 以反引号开头的表达式整行加引号: `` - "`本期.金额(万元)` > 100" ``; 输出格「不改」不能写裸 `-` (YAML 当成列表项), 直接不写该列或写 `"-"`。

一份能直接 `rule-sheet test` 通过的最小文件:

```yaml
输入:
  客户: {文件: 客户客户.xlsx, 匹配: 主表}
  本月: {文件: 本月流水.xlsx, 匹配: 客户编号}

变量:
  偏差率: abs(本月.金额 - 客户.金额) / 客户.金额

规则:
  - 编号: R1
    当:
      - 本月.存在 == 是
      - 偏差率 > 0.05
    则:
      复核标记: 待复核

测试:
  - 用例: 偏差 8% 触发
    输入: {客户.金额: 10000, 本月.金额: 10800, 本月.存在: 是}
    期望: {复核标记: 待复核}
  - 用例: 本月缺失不触发
    输入: {客户.金额: 10000, 本月.存在: 否}
    期望: {}
```

## 7. 运行过程与输出

`run` 的顺序: 加载规则 → 跑内嵌测试 (有失败即停, 除非 `--ignore-tests`) → 绑定输入文件 (命令行 `-i` 优先, 否则规则里的默认文件, 都没有就报错) → 读入各表 → 以主表为锚, 每个参照表按各自的匹配键 left join 进来 → 求派生变量 → 逐条规则求命中 → 按命中策略合并 → 写出。

控制台会打印: 规则数与命中策略、每条测试用例的通过 / 失败及命中的规则、每个输入实际读的文件与行数 (主表标出)、参照表重复键提示、发生变更的行 (主表的匹配键列 + 命中规则 + 变更明细)、输出路径。

输出文件是**主表的副本**, 原表不动, 末尾多两列:

| 列 | 内容 |
|---|---|
| 命中规则 | 这一行命中了哪几条, 按优先级排, 如 `R1; R3`; 没命中为空。`首次命中` 策略下只记赢的那一条 |
| 变更明细 | 每个被改的字段 `列: 旧值 -> 新值`, 多个用 `;` 分隔; 没变化为空。被 `清空` 的列显示 `旧值 -> 空` |

写出时自动设列宽、冻结首行首列、日期列格式 `yyyy-mm-dd`。目标文件被 Excel 打开而无法写入时, 自动改用 `_v2`、`_v3` … `_v9` 后缀, 都不行才报错。

**命中策略**:

- `优先级`: 多条规则同时命中一行时, **每个输出列**取优先级数字最小、且写了该列 (不是 `-`) 的那条。没有任何规则写该列则保持原值。
- `唯一`: 任何一行命中多条规则就报错停下, 错误信息里列出匹配键值与命中的规则 ID。
- `首次命中`: 每行只算优先级数字最小的那条命中, 其余规则对这一行视为未命中 (DMN 的 First)。该行的结果就是这一条规则的输出, 它没写的列保持原值; 一条没有任何输出的规则也能把一行拦下来, 不让后面的兜底规则改它。`命中规则` 列只记这一条。同优先级按书写顺序, 优先级留空取 `1000 + 行序`, 所以**建议每条都显式写优先级**, 否则挪动一行就会改变语义。

- `多条拼接`: 每个输出列把所有命中规则写的值按优先级顺序 (同优先级按书写顺序) 用「设置」里的 `拼接分隔符` (默认 `/`) 接成一个文本, 替换原值 (DMN 的 Collect)。没写该列的规则不参与, 算出空值的规则不贡献, 没命中的行不动; 重跑不会越接越长。`命中规则` 列记全部命中。输出格在这个策略下不能写 `清空` (加载时报错)。适合多标签分类: 样例 position-tags 的 J004 同时命中四条, 标签是 `高管/直管/高职级/新推荐`。

`优先级` 与 `首次命中` 的差别只在一行命中多条时: 前者逐列合并 (适合几条规则各管各的列), 后者整行听一条 (适合状态机: 先排除、再分类、最后兜底), `多条拼接` 则是全都要。样例 `status-machine` 的 S2 在 `优先级` 下不占任何列, 会被兜底的 S4 改掉; 在 `首次命中` 下 S2 命中即停。

**数据类型**: 按 Excel 单元格类型走。设为文本格式的数字串 (电话、带前导零的编号) 按文本处理不会变数字; 数值列、日期列正常识别。各表的同名列在规则里靠输入名前缀区分 (`客户.金额` / `本月.金额`); 参照表的匹配键列不暴露 (值就是主表的)。

## 8. Python API

```python
from rule_sheet import run, run_tests, load_rules

res = run("examples/customer-sync/rules.yaml", dry_run=True)
print(res.changed[["客户编号", "命中规则", "变更明细"]])

outcomes = run_tests(load_rules("examples/customer-sync/rules.yaml"))
print([(o.name, o.passed, o.hit) for o in outcomes])
```

`run(rules_path, *, base_dir=None, inputs=None, output=None, ignore_tests=False, dry_run=False) -> RunResult`, 参数含义与命令行选项一一对应; `inputs` 是 `{输入名: 文件路径}`, 对应 `-i`。

| `RunResult` 字段 | 内容 |
|---|---|
| `ruleset` | 加载后的 `RuleSet` |
| `tests` | 每条内嵌用例的 `TestOutcome` (`name` / `passed` / `hit` / `problems` / `error`); `tests_passed` 属性是通过数 |
| `stopped_by_tests` | 为 True 时因测试失败而停止, 以下字段为空 |
| `keys` | 主表上标识一行的列 (第一个参照表的匹配键; 没有参照表就是第一列), 控制台变更表用它 |
| `inputs` | `{输入名: (实际读的文件, 行数)}` |
| `out` | 完整结果表 (主表副本 + 两列审计) |
| `changed` | `out` 中变更明细非空的行 |
| `written` | 实际写出的路径; `dry_run` 时为 None |
| `notes` | 运行提示, 如某个参照表重复键按「取第一条」处理 |

## 9. 常见报错

| 现象 | 原因与处理 |
|---|---|
| `规则文件不存在: ...` | 路径写错 |
| `规则文件缺少「输入」sheet` / `缺少「决策表」sheet` | sheet 名必须完全一致 (旧的「匹配设置」也认) |
| `「输入」sheet: 必须恰有一个输入的「匹配」写 主表 ...` | 主表那一行的「匹配」写 `主表`, 其它输入写键; 只有一个输入时可留空 |
| `「输入」sheet: 输入「X」没有写「匹配」` | 参照表必须写对齐到主表的键 |
| `「输入」sheet: 输入「X」的匹配键「...」只能对齐到主表「...」` | 键右侧只能写主表的列 (星型), 不能对齐到别的参照表 |
| `「输入」sheet 第 1 行缺少「名称」列` | 列名行要有 名称 / 匹配 (重复键 / 文件 / 说明 可选) |
| `「设置」sheet: 设置项「X」不认识` | 只认 基准日期 / 输出 / 拼接分隔符 |
| `设置了「拼接分隔符」, 但命中策略是「优先级」而不是 多条拼接` | 策略名没写或写错 |
| `规则 G1 输出「标签」= 清空: 命中策略 多条拼接 只拼接有值的输出, 不能写 清空` | `多条拼接` 下清空没有意义, 想清掉这一列换别的策略 |
| `输入「X」「Y」没有绑定文件` | 规则文件里没写默认文件, 命令行也没给 `-i X=路径` |
| `命令行给的输入「X」不是规则声明的输入` | `-i` 的名称要和「输入」里的一致 |
| `数据表不存在: ...` / `数据表 ... 里没有 sheet「X」, 有: ...` | 检查 `-i` 路径、规则里的默认文件与 `--base-dir`; `#` 后的 sheet 名要存在 |
| `主表「A」没有列「k」, 而输入「B」要按它对齐` / `输入「B」没有匹配键列「k」` | 匹配键列在两张表里都得有 |
| `输入「B」有 N 行重复键, 而它的「重复键」设置为 报错` | 参照表一对多; 设为 `取第一条` 或先去重 |
| `「决策表」sheet 找不到列类型行: ...` | 没有一行写着 `规则ID` (测试 sheet: `用例`); 表头按这个词定位, 检查拼写 |
| `「决策表」sheet C2 格的列类型「条件」不认识, 只认: ...` | 列类型行只认 规则ID / 优先级 / 输入 / 输出 / 说明 (测试 sheet: 用例 / 输入 / 期望 / 说明) |
| `「决策表」sheet C2 格标了「输入」列, 但 C3 格没有写列名` | 列类型行下一行必须是列名行, 且标了类型的列都要有名字 |
| `规则 S3 的续行 (第 7 行) 输出「状态-会议」= ..., 与首行 (第 6 行) 的 ... 不一致` | 同一规则的续行只写条件, 输出和优先级留空或与首行相同 |
| `规则ID「S3」在第 6 行和第 9 行重复出现; ... 必须写在相邻的行` | 同一规则的「或」分支要相邻; 不是同一条规则就换个 ID |
| `「测试」sheet: 期望列「X」不是输出列 (输出列: ...)` | 期望列名拼错; 不报错的话这一列会被整列忽略, 用例假通过 |
| `「测试」sheet: 输入列「X」不是规则引用到的变量, 填了也不起作用 (可用: ...)` | 输入列名拼错或漏了别名前缀; 可用的名字列在括号里 |
| `「测试」sheet 里没有任何用例` / `YAML 的 测试: 下没有任何用例` | 写上用例, 或删掉测试 sheet / `测试:` 键 |
| `规则文件没有测试用例 ..., 什么都没验证` (`test` 返回 1) | `test` 子命令对没有用例的文件不算通过 |
