# rule-sheet 使用指南

本文讲怎么用: 安装运行、规则文件的两种写法 (Excel 决策表 / YAML) 的精确格式、单元格与表达式语法、输出结果、Python API 和常见报错。为什么这样设计见 [设计架构.md](设计架构.md)。

## 1. 安装与命令

需要 [uv](https://docs.astral.sh/uv/)。在项目目录执行:

```powershell
uv sync
uv run rule-sheet run  examples/customer-sync/规则_决策表.xlsx   # Excel 决策表
uv run rule-sheet run  examples/customer-sync/rules.yaml         # 同一组规则的 YAML 版
uv run rule-sheet test examples/customer-sync/rules.yaml         # 只跑规则文件内嵌的测试用例
uv run rule-sheet run  examples/status-machine/rules.yaml -i 本期=本期岗位_2026-10.xlsx -i 上期=上期岗位_2026-09.xlsx -o 结果.xlsx
uv run rule-sheet run  examples/position-tags/规则_决策表.xlsx   # 多标签分类: 多条拼接 / 文本关键字 / 清单当参照表
uv run rule-sheet run  examples/carry-forward/规则_决策表.xlsx    # 字段组: 六列一格整组从上期带入
uv run rule-sheet run  examples/candidate-rollup/规则_决策表.xlsx  # 重复键 拼接: 一岗多条推荐记录接成一行
uv run rule-sheet run  examples/period-diff/规则_决策表.xlsx       # 两期比对: 差异() + 独有行 追加 (ADDED / CHANGED / UNCHANGED / REMOVED)
uv run rule-sheet --version
```

`rule-sheet <规则文件>` 省略子命令等价于 `run`。

模型是 **规则文件 + 输入文件 → 输出文件**。规则文件声明有哪些输入 (名字、怎么对齐到主表), 是形参; 文件是实参, 两种给法: 规则文件里写默认文件 (任务文件夹模式, 见第 2 节), 或命令行 `-i 名称=路径` (每月换数据文件不用改规则)。两种可以混用, 命令行优先。

| 子命令 / 选项 | 作用 |
|---|---|
| `run <规则文件>` | 先跑内嵌测试, 全部通过才读入各输入表、执行规则、写出结果 |
| `run -i 名称=路径` | 绑定一个输入 (可重复)。名称是规则文件「设置」的输入表里声明的; 路径相对当前目录, 可带 `#sheet名` (不带则读第一个 sheet); 覆盖规则文件里的默认文件 |
| `run -o PATH` / `--output PATH` | 覆盖规则文件里的输出路径 |
| `run --var 基准日期=2026-10-23` | 运行时给基准日期, 覆盖「设置」里的值 (见第 2 节「设置」表); 目前只认 `基准日期`, 别的名字报错 |
| `run --base-dir DIR` | 规则文件内相对路径 (默认文件 / 输出) 的基准目录, 默认规则文件所在目录; 不影响 `-i` 给的路径 |
| `run --ignore-tests` | 内嵌测试有失败也继续处理真实数据 |
| `run --dry-run` | 只打印变更, 不写文件 |
| `test <规则文件>` | 只跑内嵌测试用例, 不读数据表 |
| `format <规则.xlsx> [-o 路径]` | 按版式规范 (3.6 节) 重排 Excel 规则工作簿: 颜色、列宽、换行、冻结。默认原地改写, `-o` 写到别处。先按加载器校验结构, 结构错就报错不碰文件 |
| `export <规则文件> [-o 路径]` | 给 `.xlsx` 就导出成 YAML (无损, 默认同目录同名 `.yaml`); 给 `.yaml` 就生成规则工作簿 (只对表格子集成立, 默认同名 `.xlsx`, 版式按 3.6 套好)。导出件是生成物, 见 6.1 / 6.2 节 |
| `diff <规则A> <规则B>` | 两份规则文件 (任意组合 .xlsx / .yaml) 语义比对: 结构逐项比, 条件按用例交叉验证。一致返回 0, 有差异返回 1 并逐条打印 |

退出码: `0` 成功; `1` 测试未通过 (`run` 因此停止, 或 `test` 有失败) 或 `diff` 有差异; `2` 规则文件 / 数据有错 (打印 `错误: ...`)。

## 2. 任务目录约定

一个任务一个文件夹, 数据和规则文件放一起, 规则文件「设置」的输入表里用相对路径写默认文件, 双击 / 不带参数运行即可:

```
customer-sync/
  客户主表.xlsx        主表, 被更新的表 (规则里叫 客户)
  本月流水.xlsx        参照表, 只读 (规则里叫 本月)
  规则_决策表.xlsx     规则 (Excel 写法)
  rules.yaml           规则 (YAML 写法, 可选)
  output/              结果输出 (不进 git)
```

数据每月换文件名、或者规则要复用到别的数据上时, 规则文件里不写默认文件 (或写了也行), 运行时 `-i 客户=客户主表_2026-10.xlsx -i 本月=流水_2026-10.xlsx` 绑定。

## 3. 规则文件: Excel 决策表写法

一个 `.xlsx`, 最多五张 sheet。sheet 名固定; `设置` 与 `决策表` 必须有 (「设置」里至少要有输入表), `变量定义`、`字段组`、`测试` 可选。0.7 以前单独的「输入」sheet 仍能读 (保留一个版本, 见 README「从 0.7 升级」)。

### 3.1 设置: 设置项与输入表

「设置」sheet 是这份规则「怎么跑」的工程侧配置, 上下两块 (0.8 起; 以前输入表是单独的「输入」sheet):

```
设置项   |                   | 每行一项: A 列名字 / B 列值 …   ← 标题行 (可省, B 列留空)
基准日期 | 2026-10-19        | 说明 (可写可不写, 浅黄)          ← 上方: 设置项, 每行一项, 可省
输出     | output/结果.xlsx  | ...
(空行)
输入表   |                   | 下一行是列名, 之后每行一个输入 … ← 标题行 (可省, B 列留空)
名称 | 匹配     | 重复键   | 文件          | 说明             ← 下方: 输入表, 从写着 名称 / 匹配 的那一行开始
客户 | 主表     |          | 客户主表.xlsx |
本月 | 客户编号 | 取第一条 | 本月流水.xlsx |
```

**设置项**: 每行第一个有字的格是设置项, 紧挨着它右边一格是值, 再往右是说明; 值留空的行跳过, 所以 `设置项` / `输入表` 两个标题行 (B 列留空, 说明写在 C 列) 只是给人看的, 样例和 `rule-sheet export` 生成的工作簿都带着。只认下表里的项, 写别的报错。没有设置项时输入表从第 1 行开始。

| 设置项 | 值 |
|---|---|
| 基准日期 | `天数差` 等计算用的「今天」; 不填取运行当天。固定下来可保证每次结果一致。每批不同的 (批次日 / 例会日) 在运行时给: 命令行 `--var 基准日期=2026-10-23`, Python `run(..., variables={"基准日期": ...})`, 覆盖这里的值, 这种场景这里可以留空。内嵌测试用例的日期写在「测试」sheet 表头上方 (3.4 节, 0.8.3); 没写那里时用例才用这里的值, 这时就别删。运行提示里会写这次用的是哪个 (`基准日期 = 2026-10-23 (运行时给定)` / `(规则文件「设置」)` / `(规则文件没设, 取运行当天)`) |
| 输出 | 默认输出路径, 相对规则文件所在目录; 不填为 `output/<主表文件名>_更新后.xlsx`; 命令行 `-o` 可覆盖 |

`多条拼接` 的 `拼接分隔符` 不在这里, 写在决策表左上角、`命中策略` 下面一行 (3.3 节): 它决定规则怎么合并结果, 和策略放一起。

**输入表** 声明规则有哪些输入: 写着 `名称` 和 `匹配` 的那一行是列名 (列的顺序随意), 之后一行一个输入, 输入表下面不要再写别的。

| 列 | 必填 | 内容 |
|---|---|---|
| 名称 | 是 | 规则里引用这张表的列时用的前缀, 如 `客户` → `客户.状态`。不能重复 |
| 匹配 | 是 | **主表那一行写 `主表`** (输出的行就是它的行, 规则写回的是它的列; 只有一个输入时可留空)。其它输入写对齐到主表的键: 两边同名写 `岗位编码`, 不同名写 `工号 = 客户.拟任人工号` (本表的列 = 主表的列), 多个键逗号分隔 |
| 筛选 | 否 | 参照表在匹配之前只留这个表达式成立的行 (0.8.1, 见下), 如 `清单.配置类别 == "职能部门"` |
| 重复键 | 否 | 参照表里同一个键出现多行时: `取第一条` (默认) / `报错` / `拼接` (0.7: 同键的行接成一行, 见下) |
| 排序 / 分隔符 / 空值占位 / 带序号 | 否 | 只在 `重复键` 写 `拼接` 时允许写 (其它策略下写了报错), 见下 |
| 独有行 | 否 | 参照表里键在主表找不到的行: `忽略` (默认) / `追加` (0.7: 接到输出行集末尾, 见下) |
| 文件 | 否 | 默认绑定的文件, 相对规则文件所在目录, 可带 `#sheet名`。不写则必须在命令行 `-i` 给 |
| 说明 | 否 | 不参与解析 |

| 名称 | 匹配 | 重复键 | 文件 |
|---|---|---|---|
| 客户 | 主表 | | 客户主表.xlsx |
| 本月 | 客户编号 | 取第一条 | 本月流水.xlsx |

参照表可以有任意多个, 各自对齐到主表 (星型); 没有参照表也行 (只按规则改一张表)。参照表键列为空的行不参与匹配; 内置变量 `<参照表名>.存在` 表示主表这一行在该参照表里是否匹配到。

**一对多的参照表: `重复键` 写 `拼接` (0.7)**。一个岗位有多条推荐记录、一个人有多条冻结记录时, 同一个键的多行在匹配之前先接成一行, 每一列各自接成一个文本, 规则层仍然逐行: 输出格直接复制 `推荐.工号` 就是 `E2;E1;E3`。四个可选项:

| 列 | 含义 |
|---|---|
| 排序 | `推荐时间 降序, 工号 升序`; 不写方向默认升序; 空值一律排末尾。不写按文件里的顺序 |
| 分隔符 | 默认 `;`。和 `多条拼接` 的 `拼接分隔符` (默认 `/`) 是两个概念: 一个接同一个键的多条记录, 一个接多条规则的输出 |
| 空值占位 | 空格子换成它 (如 `NA`), 位置保留, 各列之间按位置对齐 (第 k 个工号对应第 k 个姓名); 整组全空输出 `NA;NA`。不写则换成空文本 (`a;;c`), 整组全空为空值 |
| 带序号 | `是` / `否` (默认): `1.审计;2.纪律`, 占位符也带序号 |

| 名称 | 匹配 | 重复键 | 排序 | 空值占位 | 带序号 | 文件 |
|---|---|---|---|---|---|---|
| 岗位 | 主表 | | | | | 岗位清单.xlsx |
| 推荐 | 岗位编码 | 拼接 | 推荐时间 降序 | NA | | 推荐记录.xlsx |
| 冻结 | 工号 = 岗位.现任工号 | 拼接 | 冻结开始 降序 | | 是 | 冻结记录.xlsx |

要在聚合**之前**对参照表的每一行先算点东西 (把部门 / 岗位 / 职级拼成「现岗」), 在「变量定义」里写名字带输入前缀的派生变量 (3.2 节): `推荐.现岗 = 拼接(推荐.现部门, "-", 推荐.现岗位, "-", 推荐.职级)`。样例 `examples/candidate-rollup/`。

**参照表独有的行: `独有行` 写 `追加` (0.7)**。「上期有、本期没有」的岗位要在输出里标成 REMOVED 时, 给上期这一行写 `独有行: 追加`: 上期里键在主表找不到的行接到输出行集的**末尾** (保持上期里的先后), 同名列的值自动带入, 键列按「匹配」的映射填好 (`工号 = 全量表.拟任人工号` 这种也对), 主表独有的列为空; 这些行和其它行一样跑全部规则、一样进审计列, 其它参照表也照常对齐到它们。内置变量 `<主表名>.存在` 在追加来的行上是 `否`, 其余行是 `是` (没有任何输入写「追加」时恒为 `是`):

| 名称 | 匹配 | 独有行 | 文件 |
|---|---|---|---|
| 本期 | 主表 | | 本期.xlsx |
| 上期 | 本岗编码 | 追加 | 上期.xlsx |

| 规则ID | 本期.存在 | 差异类型 |
|---|---|---|
| X1 | 否 | REMOVED |

多个输入都写「追加」时按声明顺序逐个做, 后面的输入先对齐到已有的行 (含前面追加的), 对不上才追加, 同一个键不会出现两行; `重复键: 拼接` 的参照表追加的是聚合后的那一行。Python API 的 `res.out` 就是扩展后的行集, 直接调 `apply_rules()` 的话用 `engine.primary_frame(rs, ns, 主表原有列)` 取扩展后的主表。

**清单 / 白名单文件也是参照表**: 「本岗编码属于某清单」不需要新语法, 把清单文件声明成一个输入 (匹配 = 清单里的编码列, 对齐到主表), 条件写 `<清单名>.存在` = `是`。清单里多出来的行不影响, 同一份清单要对主表两列用 (本岗编码 / 拟任岗位编码) 就声明两次、起两个名字。多个清单放在一个工作簿里时用 `文件: 配置表.xlsx#职能部门`。样例 position-tags 的 `关键岗位清单` 就是这么写的。

**参照表只取一部分行: `筛选` (0.8.1)**。一张配置表里混着几类配置 (`配置类别` 列区分)、或者只该用当前有效的配置时, 给这个输入写 `筛选`: 一个逻辑表达式, 在这张表**自己的行上**、对齐到主表**之前**算, 只留成立的行。同一个文件声明几个输入、各写各的筛选, 就各取一类:

| 名称 | 匹配 | 筛选 | 文件 |
|---|---|---|---|
| 本期 | 主表 | | 本期.xlsx |
| 职能部门 | 配置项 = 本期.一层组织 | `职能部门.配置类别 == "职能部门"` | 配置清单.xlsx |
| 销服群 | 配置项 = 本期.岗位群 | `销服群.配置类别 == "销服岗位群"` | 配置清单.xlsx |

- 表达式就是第 5 节的那套: 文字加引号, `且` / `或` / `非`, `in ("A", "B")`, 比较, 函数都能用; 有效期写 `清单.生效日期 <= 基准日期 且 (清单.失效日期 == 空 或 清单.失效日期 > 基准日期)` (运行时 `--var 基准日期=` 给的也生效)。空值参与比较不成立, 那一行就被筛掉
- 只能引用**这张表自己的列** (`<本输入名>.<列>`, 含它带前缀的派生变量) 和 `基准日期`: 筛选发生在对齐之前, 别的表还没进来, 引用了加载时就报错。主表不能写筛选: 输出的行就是主表的行, 只想改其中一部分行写在规则条件里
- 每张参照表的处理顺序: 剔掉键为空的行 → 带前缀的派生变量 → **筛选** → 重复键 (取第一条 / 报错 / 拼接) → 独有行追加 → 对齐到主表。筛选在去重之前, 所以别的类别里出现的同名配置项不算重复, 也不会被「取第一条」挑中
- 为什么不在规则里判类别: 规则里写 `职能部门.配置类别 == "职能部门"` 只能防住「别的类别被当成这一类」; 同一个配置项在两类里都有时, 对齐时已经按「取第一条」只留下一行, 留下的若是另一类, 这一类就漏了, 规则层补不回来
- 运行提示写明保留了几行 (`输入「职能部门」按筛选保留 38 / 175 行`); **一行都没留下时报错** (多半是值写错了: 多了空格、全角半角不一致), 不让这个输入的 `.存在` 整列静默变成 `否`
- 内嵌测试用例直接给 `<输入名>.存在` 的值, 测不到筛选 (和匹配键一样, 它们属于匹配层); 上面的提示与报错是这一层的护栏。样例 position-tags 的 `关键岗位清单` 混着 `保密岗位` 一类, 靠筛选只取 `关键岗位`

0.4 以前的「匹配设置」sheet (左表 / 右表 / 左表别名 / 右表别名 / 匹配键 / 右表重复键) 仍能读, 自动折算成上面的声明; 对照表见 README「从 0.4 升级」。

### 3.2 变量定义 (可选)

第 1 行表头, 之后每行: A 列变量名、B 列表达式。A 或 B 为空的行忽略 (可以用来写备注)。按行顺序求值, 后面的可以引用前面的。

```
偏差率          abs(本月.金额 - 客户.金额) / 客户.金额
距上次活跃天数  天数差(基准日期, 客户.上次活跃)
```

表达式语法见第 5 节。

**名字带输入前缀的派生变量** (0.7): `推荐.现岗 = 拼接(推荐.现部门, "-", 推荐.现岗位, "-", 推荐.职级)` 在推荐记录**自己的每一行**上算, 发生在匹配 / 聚合之前, 只能引用同一张表的列 (和 `基准日期`); 算完就是那张表的一列, 规则里当普通变量用 (`推荐.现岗`)。它是「重复键 `拼接`」的搭档: 先逐行组合, 再按键接成一行。和主表同名的也行 (`本期.x`), 效果与普通派生变量相同。测试用例里它直接给值、不推导 (3.4 节)。

### 3.3 决策表

两行表头 (列类型行 + 列名行), 之前可以放元信息, 之后每行一条规则。**表头按内容识别**: 写着 `规则ID` 的第一行就是列类型行, 下一行是列名行, 不固定在第几行。

| 行 | 内容 |
|---|---|
| 元信息行 (可选, 任意行数) | 命中策略: 一格写 `命中策略`, 右边一格写策略名 `优先级` (默认) / `唯一` / `首次命中` / `多条拼接`, 写别的报错; 没有这一行取默认。各策略的语义、怎么选、「优先级」列怎么用见 7.1 节。拼接分隔符 (0.8 起在这里): 一格写 `拼接分隔符`, 紧挨着的右边一格写分隔符 (默认 `/`, 可以是空格; 留空就是默认, 不会把再右边的说明当成分隔符), 只在 `多条拼接` 下能写, 别的策略下写了报错 (多半是策略名写错)。其余格可写说明 |
| 列类型行 | 每列的类型: `规则ID` (恰好一列) / `优先级` (可选) / `输入` / `输出` / `说明` (可选)。拼错报错; 留空的列不参与解析 |
| 列名行 | 每列的名字: 输入列填变量名 (如 `客户.状态`、`偏差率`), 输出列填主表要写回的列名 (如 `状态`)。标了类型的列没写名字报错 |
| 正文 | 每行一条规则。`规则ID` 为空的行跳过; `优先级` 数字越小越优先, 留空取 `1000 + 行序` (即排在所有写了优先级的规则之后, 按行序), 详见 7.1 节 |

输入格写单元格条件 (第 4 节), 输出格写要写回的值 (第 4.2 节)。同一行的各输入格之间是 AND。

**跨变量的「或」: 相邻几行写同一个规则 ID**, 它们是同一条规则的几个分支, 每行内各格 AND、行间 OR。优先级、说明以首行为准 (续行的优先级留空或与首行相同, 否则报错); 续行的输出格留空 = 与首行相同。规则 ID、优先级、输出格都可以合并单元格, 合并区域按左上格的值算。不相邻的重复 ID 报错。样例 status-machine 的 S3:

| 规则ID | 优先级 | 本期.类别-会议 | 上期.类别-会议 | 拟任人有变化 | 流程节点有变化 | 状态-会议 |
|---|---|---|---|---|---|---|
| S3 | 3 | - | = 本期.类别-会议 | 是 | - | 02-进展更新 |
| S3 | | - | = 本期.类别-会议 | - | 是 | |

等价于 YAML 的 `任一满足:`。分支多、或者「或」有业务含义时, 另一种写法是在「变量定义」里用 `或` 组合成一个派生变量 (如 `有变化: 拟任人有变化 或 流程节点有变化`), 决策表里只留一列。

**续行可以有各自的输出 (0.7)**: 续行的输出格写了与首行不同的值, 这条规则就是「有各自输出的几个分支」。规则整体参与命中策略 (计一次), 审计列记规则 ID; 规则对一行写什么由分支决定, **合并方式跟随命中策略** (策略本身见 7.1 节): `多条拼接` 下所有成立分支的值按书写顺序接起来 (相同值只记一次); `首次命中` / `优先级` / `唯一` 下取书写顺序第一个成立的分支 (无条件的一行就是规则内的兜底)。样例 position-tags 的 G6 (`多条拼接`):

| 规则ID | 优先级 | 岗位.岗位名称 | 岗位.一层组织 | 职能 |
|---|---|---|---|---|
| G6 | 6 | - | 开头是 5- | 职能平台 |
| G6 | | 包含 财务, 会计 | - | 财务 |
| G6 | | 包含 法务 | - | 法务 |
| G6 | | 包含 采购, 供应 | - | 供应链 |

`5-职能平台` 的「财务部-会计」两支都成立, 职能是 `职能平台/财务`。续行留空的输出格继承首行, 所以一个分支没法表达「这一列我不写」而首行写了; 要那样就拆成不同规则。

以 `=` 开头的格 (`= 活跃`、`= 本期.类别-会议`、`=客户.金额 * 1.1`) 在 Excel 里输入时会被当成公式, 显示 `#NAME?`。rule-sheet 读的是格里的原文, 所以照样能用; 想让它显示正常, 先把单元格设成文本格式再输入, 或以 `'` 开头。规则工作簿里不要写真正的 Excel 公式, 读到的会是公式原文而不是计算结果。

### 3.4 测试 (可选)

与决策表同样的两行表头: 列类型行 (`用例` 恰好一列 / `输入` / `期望` / `说明`) 和列名行 (输入列填变量名, 期望列填输出列名), 按写着 `用例` 的行识别, 可以直接从第 1 行开始。之后每行一个用例, `用例` 为空的行跳过。

- 输入格直接写变量的值 (不是条件)。`<参照表名>.存在` 这一列写 `是` / `否`。留空或写 `空` = 该变量为空值。`<主表名>.存在` 没给 = `是` (普通行), 写 `否` = 「独有行: 追加」追加来的行。
- 决策表引用了、但用例没有这一列的变量, 一律视为空值。
- 期望格留空 = **该列不变**。有值 = 执行后该列应等于此值。写 `空` (或 `清空`、`为空`) = 执行后该列应为空值, 用来验证 `清空` 输出; 留空和 `空` 不一样, 前者抓「不该动的被动了」, 后者抓「该清的没清」。
- 派生变量 (变量定义里的) 可以直接在输入里给值, 给了就不再推导; 留空或没有这一列则按表达式推导 (推导用到的列也可以在输入里给), 推导失败置空。
- **名字带输入前缀的派生变量 (`推荐.现岗`) 和 `重复键: 拼接` 聚合出来的列, 在用例里直接给拼好的文本** (`E2;E1;E3`), 不推导: 真实数据里它们在聚合前 / 聚合时算好, 用例里从聚合后的文本再推导是错的。没给就是空值。
- **列名在加载时校验**: 期望列必须是决策表的输出列 (字段组展开后的逐列, 不是组名); 输入列必须是规则引用到的变量 (表头输入列, 以及输入格右侧 `!= 上期.电话`、输出格 `=客户.金额 * 1.1` / `本月.电话` 里引用的, 字段组展开出来的 `上期.例会时间`)、派生变量或其表达式里引用的列、`<参照表名>.存在`、`基准日期`, 或 `<主表名>.<输出列>` (给输出列的原值)。对不上就报错, 因为拼错的期望列会被整列忽略、拼错的输入列填了不起作用, 用例会「假通过」。
- 有「测试」sheet 但一条用例都没有也报错; `rule-sheet test` 对没有用例的规则文件返回 1。

**用例的基准日期 (0.8.3)**。规则里用到 `基准日期` 时 (`>= 基准日期 - 365天`、`=基准日期`、筛选里的有效期), 用例的期望是按某个固定日期写的: 「正好 365 天, >= 成立」只在那一天成立。所以这个日期跟着用例走, 写在「测试」sheet 表头上方, 和决策表左上角的 `命中策略` 同一种写法:

```
基准日期 | 2026-10-20 | 用例是按这个日期写的 (说明, 可写可不写)
用例     | 输入          | 输入 ...                     ← 列类型行
用例     | 本期.本批冒泡 | 上期.存在 ...                ← 列名行
T1       | 是            | 是 ...
```

| 用例里的 `基准日期` 取哪个 | 说明 |
|---|---|
| 1. 用例自己的 `基准日期` 输入列 | 个别用例要测别的日期 (跨年、月末) 时给这一列 |
| 2. 「测试」sheet 表头上方的 `基准日期` | 这组用例的日期, 推荐写在这里 |
| 3. 「设置」的 `基准日期` | 0.8.2 以前只能写在这里, 照旧认 |
| 4. 都没有 | 规则引用了 `基准日期` 时这些用例**记为出错** (按运行当天算会今天过、明天挂): `rule-sheet test` 不通过, `run` 照常在测试这一步停下, `--ignore-tests` / `ignore_tests=True` 仍可继续处理真实数据; 没引用基准日期的不受影响 |

运行时给的 `--var 基准日期=` / `variables=` **只作用于真实数据, 不影响用例**: 用例的期望是按固定日期写的, 换成批次日期就错了。所以每批日期不同的场景 (例会日、批次日) 推荐: 「设置」的 `基准日期` 留空或不写, 每批跑的时候 `--var` 给; 「测试」sheet 表头上方写用例的日期。这样「设置」里不会再有一个「看着像业务配置、其实只给测试用」的日期。样例 carry-forward 就是这么写的。`rule-sheet test` 会打印用例用的是哪个日期。

### 3.5 一张决策表长什么样

以自带样例为例 (颜色只是视觉提示, 解释器不读颜色):

| 规则ID | 优先级 | 客户.状态 | 偏差率 | 本月.存在 | 距上次活跃天数 | 本月.电话 | 状态 | 电话 | 复核标记 | 备注 |
|---|---|---|---|---|---|---|---|---|---|---|
| R1 | 1 | 活跃 | > 0.05 | 是 | - | - | - | - | 待复核 | 金额偏差超 5% |
| R2 | 2 | != 休眠 | - | 否 | > 180 | - | 休眠 | - | - | 连续 6 个月无流水 |
| R3 | 3 | - | - | 是 | - | != 客户.电话 | - | 本月.电话 | - | 电话变更 |

### 3.6 版式规范与 `rule-sheet format`

解释器不读颜色和列宽, 但一张好读的表对业务人员很重要。版式是一套固定规范, 定义在 `rule_sheet/style.py`: 样例生成脚本只写内容, 版式由它套; 业务人员在 Excel 里改乱了, `rule-sheet format 规则.xlsx` 一键恢复 (默认原地改写, 文件被 Excel 打开时报错而不是写副本)。

| 项目 | 规范 |
|---|---|
| 列类型配色 | 输入 浅蓝 `DDEBF7` / 输出 与 期望 浅绿 `E2EFDA` / 说明 浅黄 `FFF2CC` / 规则ID 优先级 用例 浅灰 `EDEDED` (只在表头)。表头与正文同色, 黄色 = 注释、不参与解析 |
| 键值 sheet (变量定义 / 字段组, 「设置」的输入表) | 表头行灰底 `D9D9D9` 加粗 (「设置」是输入表的列名行, 其余 sheet 是第 1 行), A 列加粗, 「说明」列浅黄 |
| sheet 顺序 | 设置 / 变量定义 / 字段组 / 决策表 / 测试 (旧的 输入 / 匹配设置 紧跟「设置」), 不认识的 sheet 排最后、相互顺序不变; 打开时停在「设置」, 只选中这一张 (多张同时选中 Excel 会进「组合工作表」, 一改改多张)。解释器按名字找 sheet, 不看顺序; 自己脚本生成的工作簿顺序乱了跑一次 `format` 即可 |
| 「设置」的分段标题行 | 值为空又不是设置项的行 (样例里的 `设置项` / `输入表` 两行) 深蓝底 `305496` 白字, 横跨到输入表的最后一列, 把两块内容隔开; 说明合并到表宽换行 (白字溢出到色带外就看不见了) |
| 「设置」的设置项行 | 设置项加粗, 值不着色, 再往右的说明浅黄、合并到输入表的最后一列并换行 (右边还有别的字就不合并, 免得清掉); 设置项与值所在的 A / B 列在输入表算出的宽度上按它们放宽 (仍在区间内) |
| 字体 / 边框 / 对齐 | 表头加粗; 表区域细灰边框; 垂直居中; 输入 与 ID 类列水平居中, 输出 / 说明 左对齐 |
| 列宽 | 按内容算 (中文按 Excel 实测算 2.2 个字符宽, 另加 2 留白), 决策表左上角的 `命中策略` / `拼接分隔符` 标签和值、「设置」的设置项和值也参与定宽 (它们右边有字, 不能溢出), 每类列有区间: 规则ID 8–12 / 优先级 8–10 / 用例 8–12 / 输入 10–28 / 输出 10–40 / 期望 10–28 / 说明 24–60; 键值 sheet 按列名: 名称 10–16 / 匹配 10–28 / 重复键 8–12 / 文件 14–36 / 设置项 12–16 / 值 16–40 / 变量 12–24 / 定义 24–60 / 说明 30–70 |
| 换行与行高 | 内容超过列宽上限的格换行 (不再加宽), 行高按估算的行数显式写入 (每行 15 磅), 各种查看器表现一致; 估算偏差时 `format` 重算 |
| 冻结 | 决策表 / 测试: 冻结到列名行之下、最左边连续 ID 类列 (规则ID / 优先级 / 用例) 之右; 「设置」: 冻结到输入表列名行之下; 其它 sheet 冻结首行 |
| 元信息行 (决策表 / 测试表头之上) | `命中策略` / `拼接分隔符` / 测试的 `基准日期` 标签加粗, 紧挨着的值不着色; 再往右的说明浅黄、合并到表的最后一列并换行, 不参与定宽 (以前溢出到表外的空白格里, 看起来和表脱开)。没有标签、只写一格策略名的旧写法: A 列加粗, 其余浅黄, 不合并 |
| 单元格格式 | 以 `=` 开头的格存为文本 (否则 Excel 当公式显示 `#NAME?`); 日期格 `yyyy-mm-dd` |

`format` 用加载器同一套逻辑找表头, 所以它和解释器对「哪里是表头」永远一个答案。openpyxl 往返会保留批注、数据验证、条件格式, 但会丢图片和图表; 规则工作簿里一般没有这些。没标类型的列 (备注列) 不着色、不参与定宽。

### 3.7 字段组 (可选, 0.7)

要把十几列一次性从参照表带过来 (跨批次同步、历史记录带入), 逐列写既冗长又容易拼错列名。「字段组」sheet 给一组列起个名字: 第 1 行表头 (`名称` / `列名` / `说明`), 之后每行一个组, 「列名」格里逗号分隔。

| 名称 | 列名 |
|---|---|
| 会议记录 | 例会时间, 类别-会议, 状态-会议, 例会结论, 备注, 待跟进事宜 |

决策表里以组名为列名的输出列 (列类型仍写 `输出`), 格里写:

| 写法 | 含义 |
|---|---|
| `上期` (一个输入名) | 组内每一列从该输入的同名列复制, 等于逐列写 `上期.例会时间`、`上期.类别-会议` … |
| `清空` | 整组清空 |
| `-` 或留空 | 整组不改 |

同一条规则里显式写了的列以显式为准: 样例 carry-forward 的 R1 写 `会议记录 = 上期` 又写 `例会时间 = =基准日期`, 例会时间按显式的算。带入是整组同步, 参照表那一格为空时主表这一列也会被清成空 (变更明细记 `旧值 -> 空`)。

加载时就展开成逐列: 引擎、审计列 (变更明细逐列记)、测试用例 (期望按列写, 不能写组名) 看到的都是逐列; `rule-sheet export` 两个方向都保留组的写法 (YAML 顶层 `字段组:`), `diff` 比组的定义。字段组还有第二个用处: 表达式里的 `差异(本期, 上期, 对比字段)` 按它逐列比两期 (第 5 节), 样例 `examples/period-diff/`。加载时报错的: 组名与输入名重复、组名是某个组里的列名、组里的列重复、组没有列、格里写了输入名 / 清空 / `-` 之外的东西 (多半是输入名拼错)。组名与主表真实列同名在读到数据时报错, 因为那一列会永远写不到。

## 4. 单元格语法

### 4.1 输入格 (条件)

| 写法 | 含义 |
|---|---|
| `-` 或留空 (也认 `—`、`任意`) | 不关心 |
| `活跃` | 等于。裸文字按文本比较; Excel 里设成数字 / 日期格式的格按数字 / 日期比较 |
| `"VIP 小幅偏差, 关注"` | 值本身含逗号时加引号 (单双引号都可), 否则会被当成枚举拆开 |
| `> 0.05` `>= 180` `< 1` `<= 1` | 比较 |
| `= 活跃` `== 活跃` | 等于 (显式写法) |
| `!= 休眠` `<> 休眠` | 不等于 |
| `!= 客户.电话` | 比较的右侧可以是另一个变量名 |
| `[0.02..0.05]` | 闭区间; `(` `)` 为开区间, 可混用如 `(0..1]` |
| `VIP, 金卡` | 枚举: 逗号分隔, 任一满足。每一项都可以是上面任何写法, 如 `> 10, 为空` |
| `= 空` / `!= 空` | 判空。`为空` / `非空` 是同义写法, 单独一个 `空` 等于 `= 空`。`空` 是关键字, 要匹配文字「空」加引号; `> 空`、`[空..5]` 报错 |
| `not(...)` | 取反。只对有值的格成立, 例外: `not(空)` / `not(为空)` / `not(非空)` 是纯否定 |
| `包含 CEO, 总裁` / `不包含 助理` | 子串匹配, 按字面 (不是正则), 逗号分隔的几项任一命中; 也可写 `包含(CEO, 总裁)`。项按原文取 (`开头是 01` 的 01 不会变成数字), 恰好是变量名的换成那一列 (`包含 本期.姓名`), 要当文字就加引号。空值不成立, `不包含` 对空值也不成立 (有值且一个都不含才成立) |
| `开头是 2-, 3-` / `开头不是 11-` / `结尾是 部` / `结尾不是 部` | 前缀 / 后缀匹配, 规则同上。关键字后面要有空格或括号, 单元格值恰好是「包含测试」这样的文字时仍按普通文字比较 |
| `是` / `否` | 仅当被比较的列是布尔列 (如 `本月.存在`) 时转成真 / 假 (也认 `true` / `false` / `yes` / `no`); 文本列里就是文字 |
| `2026-10-19` | 日期字面量 |

**空值规则**: 空值参与任何比较 (等于、不等、大小、区间、枚举) 都不成立。要判空必须显式写 `= 空` / `!= 空` (或 `为空` / `非空`); 枚举里也可以放 `空`: `活跃, 空` = 活跃或为空。`= 空` 是唯一把「空」当成可比对象的写法, `= 客户.电话` 在两边都为空时仍不成立。

### 4.2 输出格

| 写法 | 含义 |
|---|---|
| `-` 或留空 | 不改 |
| `待复核` | 写入这个字面值 (Excel 里的数字 / 日期格原样写入) |
| `"本月.电话"` | 加引号表示强制当文字, 即使它长得像变量名 |
| `本月.电话` | 恰好是一个变量名时, 复制该变量的值 |
| `=客户.金额 * 1.1` | 以 `=` 开头是表达式, 按第 5 节求值。「条件 A 时写 X 否则写 Y」用 `=如果(上期.x != 空, 上期.x, 基准日期)`, 拼文本用 `=拼接(本期.姓名, "(", 本期.工号, ")")` |
| `清空` (也认 `置空`、`空`、`=空`) | 把该列写成空值。和 `-` 不同: `-` 是不碰这一列, `清空` 是主动清掉 (变更明细显示 `旧值 -> 空`)。要写文字「清空」/「空」就加引号 |
| 字段组列下的 `上期` / `清空` / `-` | 列名是字段组名时 (3.7 节): 整组从输入 `上期` 复制同名列 / 整组清空 / 整组不改; 显式写了的列优先 |

## 5. 表达式语法 (变量定义、`=` 输出格、YAML 条件)

表达式是 Python 语义, 对整列向量化求值。可以写:

- 变量: `<输入名>.<列名>` (输入名是输入表里声明的, 如 `客户.状态`、`本月.金额`)、`<参照表名>.存在` (该参照表是否匹配到, 布尔)、`基准日期`、变量定义里的名字
- 列名含 `-`、`/`、全角括号的直接写: `本期.类别-会议 == "变动通报"`、`非空(本期.岗动-拟任命人-流程节点)`。`-` 后面紧跟 `别名.`、数字或已知名字时才是减号 (`本期.金额-上期.金额`、`本期.金额-1`、`本期.金额-偏差率`); 写减法时两边加空格最稳妥。反过来, 列名里 `-` 后面恰好是数字的 (如 `类别-2024`) 会被当成减法, 这种列名用下一条的反引号
- 列名含其它符号 (半角括号、空格、`%` 等) 的用反引号包裹整个名字: `` `本期.金额(万元)` > 100 ``。反引号里的名字必须在命名空间里, 否则报错。**YAML 里以反引号开头的表达式整行要加引号** (`` - "`本期.金额(万元)` > 100" ``), 否则 YAML 本身就解析不了; Excel 单元格不受影响
- 运算: `+ - * /`、比较 `== != > >= < <=` (可以链式: `0.02 <= 偏差率 <= 0.05`)、`in` / `not in` (`客户.等级 in ("VIP", "金卡")`)、括号
- 时长字面量 `N天` (可带小数): `本期.推荐时间 >= 基准日期 - 365天`、`基准日期 + 30天`。只有「天」, 月 / 年长度不固定不提供
- 连接词: `且` / `或` / `非` (也认 `and` / `or` / `not`), 两侧留空格, 按行逐元素运算: `非空(本期.拟任人) 且 本期.拟任人 != 上期.拟任人`
- **空值**: 所有比较任一侧为空都不成立, 与单元格一致 (`本月.电话 != 客户.电话` 在任一方为空时为假, 不会把空值当成「不同」)。判空写 `x == 空` / `x != 空` (`为空(x)` / `非空(x)` 同义); `空` 也可以放进 `属于(x, "a", 空)` / `x in ("a", 空)` 的枚举里。`空` 是关键字不是值: 只能和 `==` / `!=` 搭配, `x > 空`、`空 + 1`、`abs(空)` 报错; 两个变量都为空时 `x == y` 仍不成立。`非` / `不满足:` 是纯逻辑取反, 空值行也为真, 要排除空值自己加 `x != 空`
- 字面量: 数字、`"字符串"` (必须加引号)、`是` / `否` / `true` / `false`
- 函数:

| 函数 | 含义 |
|---|---|
| `abs(x)` `round(x, n)` | Python 内置, 对整列逐行生效 |
| `min(...)` `max(...)` | Python 内置, 只适合标量参数 (如 `min(客户.金额, 100)` 这类对整列取小会报错) |
| `天数差(晚, 早)` / `days_between(晚, 早)` | 两个日期相差的天数 |
| `非空(x)` / `为空(x)` | 判空, 返回布尔; 与 `x != 空` / `x == 空` 同义 |
| `属于(x, 值1, 值2, ...)` | x 等于任一个值 |
| `包含(x, 文本1, 文本2, ...)` / `不包含(...)` | x 含任一子串 / x 有值且一个都不含。按字面匹配, 不是正则 (`.`、`+` 就是字符本身); 非文本列先转成文本 (7.0 按 `7`, 日期按 `2026-10-01`); 文本参数也可以是列 |
| `开头是(...)` / `开头不是(...)` / `结尾是(...)` / `结尾不是(...)` | 前缀 / 后缀匹配, 规则同上 |
| `拼接(a, b, ...)` | 连成一个文本。空值当空串; **所有列参数都为空时结果是空值, 字面量不算数** (0.7 起: `拼接(x, "元")` 在 x 为空时为空而不是 `元`; `拼接(部门, "-", 岗位, "-", 职级)` 三列全空为空, 部分空出 `部门--职级`); 数字 7.0 写成 `7`, 日期写成 `2026-10-01`, 布尔写成 是 / 否 |
| `数字(x)` | 文本里的第一个数: `22级` / `P23` / `第3档` → 22 / 23 / 3, 取不到为空; 数值原样返回。Python 的 `float()` / `int()` 不开放, 用它 |
| `日期(x)` | 日期字面量 `日期("2026-10-01")` (表达式里裸写 `2026-10-01` 会被当成减法); 也能把文本日期列转成日期列, 认不出的为空 |
| `如果(条件, 真值, 假值)` | 向量化三元: 条件为真取真值, 否则取假值 (条件为空算假)。分支可以是列、字面量或 `空`, 可以嵌套 |
| `差异(新, 旧, 字段组)` | (0.7) 字段组里的每一列逐个比两个输入的同名列 (`差异(本期, 上期, 对比字段)`), 变化的拼成 `字段:旧值->新值`, 多个用 `;` 接 (可改: `差异(..., 分隔符="|")`), 没有变化为空值。相等判定与审计列同一套 (空串与空值相同, 文本严格, 数值按数值, 日期按日期); 空值显示为空串 (`拟任人:李四->`)。前两个参数写输入名, 第三个写字段组名 (3.7 节); 两个输入都要有组里的列。样例 `examples/period-diff/` |

文本函数、`拼接`、`数字` 的参数不能是 `空` (报错), 想把空值当空串拼接直接传列。

**几条规矩**:

- 字符串必须加引号: `客户.状态 == "活跃"`; 裸的 `活跃` 会被当成变量名
- 布尔列写 `本月.存在 == 是` / `== 否`, 或直接写 `本月.存在` / `非 本月.存在`
- 一个派生变量就是一个布尔列时, 条件里直接写它的名字 (`拟任人有变化`), 不用 `== 是`
- 三元写 `如果(条件, 真值, 假值)`; Python 的 `x if 条件 else y` 和对整列做 `bool()` 报「对整列做了真假判断」
- 中文连接词两侧留空格 (`a 且 b`); 紧贴着写 (`a且b`) 会被当成一个名字

## 6. 规则文件: YAML 写法

```yaml
输入:                                  # 同 Excel「设置」里的输入表: 名字 -> {文件, 匹配, 重复键}
  客户: {文件: 客户主表.xlsx, 匹配: 主表}                     # 主表: 输出的行就是它的行
  本月: {文件: 本月流水.xlsx, 匹配: 客户编号, 重复键: 取第一条}  # 按 客户编号 对齐到主表; 重复键 可省
  # 花名册: {匹配: 工号 = 客户.拟任人工号}                    # 参照表可以有任意多个; 不写 文件 就得在命令行 -i 给
  # 推荐: {文件: 推荐记录.xlsx, 匹配: 岗位编码, 重复键: 拼接, 排序: 推荐时间 降序, 空值占位: NA, 带序号: 是}   # 一岗多行接成一行 (3.1 节)
  # 上期: {文件: 上期.xlsx, 匹配: 岗位编码, 独有行: 追加}   # 上期有本期没有的行接到输出末尾, 本期.存在 == 否 (3.1 节)
  # 职能部门:                                               # 一个文件混着几类配置, 只取一类 (3.1 节)
  #   文件: 配置清单.xlsx
  #   匹配: 配置项 = 客户.一层组织
  #   筛选: 职能部门.配置类别 == "职能部门"

设置:                                  # 可省
  基准日期: 2026-10-19                  # 可省, 默认运行当天
  输出: output/客户主表_更新后.xlsx     # 可省, 默认 output/<主表文件名>_更新后.xlsx

变量:                                  # 可省; 有序, 后面的可引用前面的
  偏差率: abs(本月.金额 - 客户.金额) / 客户.金额
  距上次活跃天数: 天数差(基准日期, 客户.上次活跃)

命中策略: 优先级                        # 可省, 默认 优先级; 或 唯一 / 首次命中 / 多条拼接
# 拼接分隔符: /                         # 只在 命中策略: 多条拼接 时用, 默认 /; 0.8 起写在顶层 (0.7 的 设置: 里也还认)

规则:
  - 编号: R1                           # 可省, 默认 R1、R2…
    名称: 活跃客户金额偏差超 5% 需复核    # 可省, 只作说明
    优先级: 1                          # 可省, 默认 1000 + 序号
    当:                                # 条件树, 见下; 省略 = 无条件命中
      - 客户.状态 == "活跃"
      - 本月.存在 == 是
      - 偏差率 > 0.05
    则:                                # 输出列 -> 值, 值的写法同 Excel 输出格; 省略 = 命中但什么都不改
      复核标记: 待复核
      备注: 金额偏差超 5%
      提醒: 清空                       # 把该列写成空值; 不想碰的列直接不写 (裸 - 在 YAML 里是语法错误, 要写 "-")

  - 编号: R5
    优先级: 5
    当:
      - 本月.存在 == 是
      - 任一满足:                      # OR
          - 本月.电话 == 空              # 判空 (为空(本月.电话) 同义)
          - 客户.电话 == 空
    则:
      提醒: 电话有缺失

测试:                                  # 可省
  - 用例: T1 偏差 8% 触发 R1            # 可省, 默认 T1、T2…
    输入: {客户.状态: 活跃, 偏差率: 0.08, 本月.存在: 是}
    期望: {复核标记: 待复核, 备注: 金额偏差超 5%}
  - 用例: T2 偏差 3% 不动
    输入: {客户.状态: 活跃, 偏差率: 0.03, 本月.存在: 是}
    期望: {}                           # 空 = 什么都不变
```

用例的期望依赖基准日期时 (3.4 节), `测试:` 写成字典, 给这组用例一个日期 (对应「测试」sheet 表头上方那一行); 只认 `基准日期` / `用例` 两个键:

```yaml
测试:
  基准日期: 2026-10-20                 # 用例按它写; --var / variables= 不影响用例
  用例:
    - 用例: T1 冒泡且上批没有
      输入: {本期.本批冒泡: 是, 上期.存在: 否}
      期望: {例会时间: 2026-10-20, 状态-会议: 01-新增}
```

**条件树** (`当:` 的内容):

| 写法 | 含义 |
|---|---|
| 一个字符串 | 一条表达式 |
| 列表 | 全部满足 (AND) |
| `全部满足: [...]` | AND, 显式写法 |
| `任一满足: [...]` | OR |
| `不满足: <子条件>` | NOT |

三者可以互相嵌套。`当:` 省略或为空 = 无条件命中所有行。`任一满足:` 对应决策表里的「多行同一个规则 ID」; 表达式内部也可以直接用 `且` / `或`, 两种写法任选。规则 `编号` 不能重复。

**分支** (`分支:`, 对应决策表里续行各自填输出, 3.3 节): 一条规则的几个有序分支, 每支自己的 `当:` / `则:`; 规则级的 `当:` 是各分支共有的条件, 规则级的 `则:` 是各分支的默认值 (分支的 `则:` 按列覆盖)。合并方式跟随命中策略: `多条拼接` 下所有成立分支的值接起来 (相同值只记一次), 其它策略下取书写顺序第一个成立的分支; 规则整体计一次, 审计记规则编号。分支的 `当:` 里不能再有 `任一满足:` (决策表里一个分支就是一行)。

```yaml
  - 编号: G6
    优先级: 6
    分支:
      - 当:
          - 开头是(岗位.一层组织, "5-")        # 表达式含逗号, 用块式列表 (流式 [ ] 会在逗号处拆开)
        则: {职能: 职能平台}
      - 当:
          - 包含(岗位.岗位名称, "财务", "会计")
        则: {职能: 财务}
      - 则: {职能: 其他}          # 无条件 = 规则内的兜底 (多条拼接 下它总成立, 注意)
```

**字段组** (顶层 `字段组:`, 对应 Excel 的「字段组」sheet, 3.7 节): 给一组列起个名字, `则:` 里写 `组名: 输入名` 就是整组从该输入复制同名列, `组名: 清空` 整组清空; 显式写的列优先。

```yaml
字段组:
  会议记录: [例会时间, 类别-会议, 状态-会议, 例会结论, 备注, 待跟进事宜]   # 也可写成一个逗号分隔的字符串
规则:
  - 编号: R1
    当: [本期.本批冒泡 == "是", 上期.存在 == 是]
    则:
      会议记录: 上期          # 展开成 例会时间: 上期.例会时间, 类别-会议: 上期.类别-会议, ...
      例会时间: =基准日期     # 显式写的列优先于字段组里的同名列
```

**YAML 的三个坑**:

- 花括号流式写法里值含逗号必须加引号: `期望: {备注: "VIP 小幅偏差, 关注"}`, 否则逗号后面会被当成另一个键。块式写法 (每行一个键) 不需要。
- 表达式里的字符串要加引号: `客户.状态 == "活跃"`; 但 `则:` 和 `测试:` 里的值是普通 YAML 值, 不加引号。
- 以反引号开头的表达式整行加引号: `` - "`本期.金额(万元)` > 100" ``; 输出格「不改」不能写裸 `-` (YAML 当成列表项), 直接不写该列或写 `"-"`。

一份能直接 `rule-sheet test` 通过的最小文件:

```yaml
输入:
  客户: {文件: 客户主表.xlsx, 匹配: 主表}
  本月: {文件: 本月流水.xlsx, 匹配: 客户编号}

变量:
  偏差率: abs(本月.金额 - 客户.金额) / 客户.金额

规则:
  - 编号: R1
    当:
      - 本月.存在 == 是
      - 偏差率 > 0.05
    则:
      复核标记: 待复核

测试:
  - 用例: 偏差 8% 触发
    输入: {客户.金额: 10000, 本月.金额: 10800, 本月.存在: 是}
    期望: {复核标记: 待复核}
  - 用例: 本月缺失不触发
    输入: {客户.金额: 10000, 本月.存在: 否}
    期望: {}
```

### 6.1 两种写法怎么保持同步

两份都手改一定会漂。做法是**定一个源, 另一个由命令生成, 用 `diff` 对账**:

- 业务人员参与的任务, **Excel 是源**。`rule-sheet export 规则.xlsx` 导出成 `规则.yaml`, 给工程侧看 git diff、做 code review; 导出件文件头写着「请勿手改」, 改了 Excel 重新导出。导出是无损的: 单元格文法的每一种形态都对应一条表达式, 翻出来的表达式在含空值的数据上与单元格的结果完全一致 (测试套件逐形态对照 `unary_test`)。

  | 单元格 | 导出的表达式 |
  |---|---|
  | `活跃` / `!= 休眠` / `> 0.05` | `客户.状态 == "活跃"` / `客户.状态 != "休眠"` / `偏差率 > 0.05` |
  | `VIP, 金卡` / `活跃, 空` | `属于(客户.等级, "VIP", "金卡")` / `属于(客户.状态, "活跃", 空)` |
  | `[0.02..0.05]` / `(0..1]` | `0.02 <= 偏差率 <= 0.05` / `0 < x <= 1` |
  | `= 空` / `非空` | `x == 空` / `x != 空` |
  | `not(活跃)` / `not(VIP, 金卡)` / `not(> 0.05)` | `x != "活跃"` / `x not in ("VIP", "金卡")` / `x != 空 且 非 (x > 0.05)` (单元格的 not 只对有值的格成立, 这样翻才一致) |
  | `包含 CEO, 总裁` | `包含(岗位.岗位名称, "CEO", "总裁")` |
  | `> 2026-10-08` | `客户.上次活跃 > 日期("2026-10-08")` |
  | 相邻同 ID 的两行 (输出相同) | `任一满足:` 下两个分支 |
  | 相邻同 ID 的几行, 各自填了输出 | `分支:` 下几项, 每项自己的 `当:` / `则:` |

  翻译约定 (导出时没有数据, 只能按约定走): 单元格 `是` / `否` 只在 `<参照表>.存在` 和派生变量上翻成布尔, 其它列翻成文字 `"是"`; 裸 `007` 和单元格里一样是数字 7, 要保文本在 Excel 里就加引号; 右侧长得像 `<输入名>.<列>` 的当变量, 其余加引号; 含半角括号、空格等符号的列名自动加反引号。

- 没有业务编辑的纯工程任务, YAML 是源, 不必生成 Excel。真要给业务人员一张表 (或者想把一份 YAML 交给业务侧接手维护), `rule-sheet export rules.yaml` 生成规则工作簿, 但只对「表格子集」成立, 见 6.2 节。

- `rule-sheet diff A B` 对账 (A、B 可以是任意组合的 .xlsx / .yaml): 结构逐项比 (输入声明、设置、变量定义、命中策略、规则 ID / 优先级 / 输出格、用例的输入与期望); 条件是编译好的函数比不了文本, 改为把两边的用例合并, 每条在两套规则上各跑一次, 比实际输出和命中规则。这是**按用例交叉验证的抽样等价, 不是证明**: 两边都没覆盖的输入组合查不出来, 用例写得越全越可靠。默认文件 / 输出路径的差异只作提示不算差异; 用例按首个词 (用例 ID) 配对, 所以 YAML 里可以写 `T1 偏差 8% 触发 R1`。

- 仓库里六个样例的 `rules.yaml` 都是手写的 (带教学注释), 不由导出覆盖; `tests/test_convert.py` 用 `diff` 守住它们与 Excel 一致, 这正是上面主张的机制在本仓库里的实例。

### 6.2 YAML → Excel: 只对「表格子集」成立

`rule-sheet export rules.yaml` 生成 `rules.xlsx` (sheet 与 Excel 写法相同, 按 3.6 的顺序: 设置 (设置项 + 输入表) / 决策表 必有, 变量定义 / 字段组 / 测试 有内容才生成; 版式按 3.6 套好, 续行的规则 ID 合并单元格)。决策表的一个格只放一个变量上的一元测试 (3.3 / 4.1 节), 所以只有写在这个子集里的 YAML 条件能转:

| YAML 条件 | 单元格 (在该变量的列下) |
|---|---|
| `客户.状态 == "活跃"` / `!= "休眠"` / `偏差率 > 0.05` | `活跃` / `!= 休眠` / `> 0.05` (字面量在左边也行, 自动翻转) |
| `0.02 <= 偏差率 <= 0.05`; 或同一规则里 `偏差率 >= 0.02` 与 `偏差率 <= 0.05` 两条 | `[0.02..0.05]` (`<` 对应开区间) |
| `属于(x, "a", "b")` / `x in (...)` / `x not in (...)` | `a, b` / `not(a, b)` |
| `x == 空` / `x != 空` / `为空(x)` / `非空(x)` / `非 (x == 空)` | `= 空` / `!= 空` / `为空` / `非空` / `非空` |
| `本月.存在 == 是` / `== 否` / 裸 `拟任人有变化` / `非 本月.存在` | `是` / `否` / `是` / `否` (只对 `<参照表>.存在` 与派生变量, 它们没有空值, 所以 `非` 在这里和 `否` 等价) |
| `包含(x, "a", "b")` 及其它文本函数 | `包含 a, b` |
| `x != 空 且 非 (...)` | `not(...)` |
| `a 且 b` (不同变量) | 同一行的两格 |
| `a 或 b` (同一变量) | 枚举 `a, b` |
| 规则顶层的 `任一满足:` (每支里全是上面的形态) | 相邻同 ID 的几行, 其余条件复制到每一行 |
| `分支:` (每支的 `当:` 里全是上面的形态, 没有嵌套的 `任一满足:`) | 相邻同 ID 的几行, 每行各自填输出 (规则级 `当:` / `则:` 合进每一行) |
| `不满足:` 包着一个判空 | 反过来的判空 |
| `x == 日期("2026-10-08")` | `2026-10-08` |

转不了的报错并指向变量定义, 都是同一个做法: 在 `变量:` 里起个名字 (`偏差率: abs(本月.金额 - 客户.金额) / 客户.金额`), 条件里只引用它。不在子集里的: 算术或函数套函数 (`abs(a - b) > 1`、`天数差(...) > 180`)、`非` 包着复合条件 (纯取反与单元格 `not` 的空值语义不同, 见 5.3 的不对称)、跨变量的 `或` (写成顶层 `任一满足:`)、嵌套的 `任一满足` / `不满足`、同一变量两个合不成区间的条件、在文本列上和 `是` / `否` 比较。

字符串字面量能裸写就裸写, 会被单元格文法认成别的东西的自动加引号: 像数字 (`"007"`)、像日期、含逗号、`是` / `否` / `空` / `-`、以比较符开头的。

## 7. 运行过程与输出

`run` 的顺序: 加载规则 → 跑内嵌测试 (有失败即停, 除非 `--ignore-tests`) → 绑定输入文件 (命令行 `-i` 优先, 否则规则里的默认文件, 都没有就报错) → 读入各表 → 以主表为锚, 每个参照表按各自的匹配键 left join 进来 → 求派生变量 → 逐条规则求命中 → 按命中策略合并 → 写出。

控制台会打印: 规则数与命中策略、每条测试用例的通过 / 失败及命中的规则、每个输入实际读的文件与行数 (主表标出)、参照表重复键提示、发生变更的行 (主表的匹配键列 + 命中规则 + 变更明细)、输出路径。

输出文件是**主表的副本** (有 `独有行: 追加` 的输入时, 末尾再接上参照表独有的行), 原表不动, 末尾多两列:

| 列 | 内容 |
|---|---|
| 命中规则 | 这一行命中了哪几条, 按优先级排, 如 `R1; R3`; 没命中为空。`首次命中` 策略下只记赢的那一条 |
| 变更明细 | 每个被改的字段 `列: 旧值 -> 新值`, 多个用 `;` 分隔; 没变化为空。被 `清空` 的列显示 `旧值 -> 空`。变更判定把空串与空值视为相同 (0.7): 原值是空串、规则写了空值不算变更 |

写出时自动设列宽 (和在 Excel 里双击列边自动调整一样: 看全部行、不换行, 上限 255; 0.8 以前只看前 50 行、上限 60, 后面更长的值会被右边的列挡住)、冻结首行首列、日期列格式 `yyyy-mm-dd`。目标文件被 Excel 打开而无法写入时, 自动改用 `_v2`、`_v3` … `_v9` 后缀, 都不行才报错。

**数据类型**: 按 Excel 单元格类型走。设为文本格式的数字串 (电话、带前导零的编号) 按文本处理不会变数字; 数值列、日期列正常识别。各表的同名列在规则里靠输入名前缀区分 (`客户.金额` / `本月.金额`); 参照表的匹配键列不暴露 (值就是主表的)。

### 7.1 优先级与命中策略

「优先级」是决策表里列类型标 `优先级` 的那一列 (YAML 里是规则下的 `优先级:` 键), 每条规则一个数字, 可选。它不是条件, 只在多条规则同时命中同一行时决定听谁的; 一行只命中一条时它无关紧要。

- **数字越小越优先。** 不必连续, 1 / 2 / 6 / 99 都行, 留出空档方便日后插规则; 按浮点读, 小数和负数都认
- **留空取 `1000 + 行序`**: 写了数字的规则永远排在没写的之前, 没写的那些之间按书写顺序
- **同一个数字按书写顺序分先后** (稳定排序, 上面的行先算)
- **同 ID 续行以首行为准**: 续行留空或与首行相同, 否则加载时报错。规则内的分支不看优先级, 按书写顺序取第一个成立的 (3.3 节)
- **审计列「命中规则」按它排序**: `R1; R3` 的先后就是优先级顺序

**命中策略**写在决策表左上角 (YAML 顶层 `命中策略:`), 决定多条规则同时命中一行时怎么用这个数字:

| 策略 | 决胜范围 | 优先级数字的作用 |
|---|---|---|
| `优先级` (默认) | 每个输出列各自 | 该列只在写了它 (不是 `-`) 的规则里取数字最小的一条; 没写该列的规则对该列既不参与也不拦截; 没有任何规则写该列则保持原值。`命中规则` 记全部命中 |
| `唯一` | 不决胜 | 任何一行命中多条就报错停下, 错误信息里列出匹配键值与命中的规则 ID; 数字只影响列出顺序 |
| `首次命中` | 整行 | 数字最小的一条赢下整行, 其余规则对这一行视为未命中 (DMN 的 First); 它没写的列保持原值, 一条没有任何输出的规则也能把一行拦下来, 不让后面的兜底规则改它。`命中规则` 只记这一条 |
| `多条拼接` | 每个输出列各自 | 所有命中规则写的值按数字顺序 (同数字按书写顺序) 用决策表左上角 (YAML 顶层) 的 `拼接分隔符` (默认 `/`) 接成一个文本, 替换原值 (DMN 的 Collect)。没写该列的规则不参与, 算出空值的规则不贡献, 没命中的行不动, 重跑不会越接越长; 输出格不能写 `清空` (加载时报错)。`命中规则` 记全部命中 |

**怎么选**:

- 几组互不相干的规则各管各的列 (两条定「岗位类型」、十几条定「类别」), 放一张表用 `优先级`: 一条规则在某列写 `-` 就是不参与那一列, 别的规则照样能写, 每列内部就是各自的 first-match, 不必拆成两个文件 (issue #27)。兜底规则照样写, 数字最大即可。从拆开的两张 `首次命中` 表合过来时, 可见的变化只有 `命中规则` 从只记赢家变成记全部命中 (如 `R1; R6; R7`), 「变更明细」不变
- 状态机 (先排除、再分类、最后兜底) 用 `首次命中`: 它独有的能力是拦截, 「命中但不写任何列」的规则在 `优先级` 下不占任何列、兜底规则照样覆盖 (样例 status-machine 的 S2)。`首次命中` 的表**建议每条都显式写优先级**, 否则挪动一行就会改变语义
- 多标签分类 (一个岗位同时是「高管」和「关键岗位」) 用 `多条拼接`: 样例 position-tags 的 J004 同时命中四条, 标签是 `高管/直管/高职级/新推荐`
- 规则本应互斥、想在加新规则时立刻暴露重叠, 用 `唯一`

同一组规则换策略结果怎么变: R1 (优先级 1) 写「备注」, R3 (优先级 3) 写「电话」和「备注」, 某行同时命中两条。`优先级` 下电话来自 R3、备注来自 R1; `首次命中` 下只有 R1 生效, 电话不变; `多条拼接` 下备注是两个值接起来、电话来自 R3; `唯一` 下报错。

用数字而不用行序决胜, 是因为 DMN 的 First 按行序决胜时挪一行就变语义 (Camunda 与 Bruce Silver 都建议避开), 这里行序只在留空时兜底; 取舍见设计架构 5.2。

**输出不回灌**: 规则条件读的都是输入, 同一张表里 R1 写出的列不会喂给 R6 的条件, 四种策略都一样。要让后面的规则依赖前面规则算出的东西, 把那个判断写进「变量定义」做派生变量, 两组规则都引用它。

## 8. Python API

```python
from rule_sheet import run, run_tests, load_rules

res = run("examples/customer-sync/rules.yaml", dry_run=True)
print(res.changed[["客户编号", "命中规则", "变更明细"]])

outcomes = run_tests(load_rules("examples/customer-sync/rules.yaml"))
print([(o.name, o.passed, o.hit) for o in outcomes])
```

`run(rules_path, *, base_dir=None, inputs=None, output=None, variables=None, ignore_tests=False, dry_run=False) -> RunResult`, 参数含义与命令行选项一一对应; `inputs` 是 `{输入名: 文件路径}`, 对应 `-i`; `variables` 是 `{名字: 值}`, 对应 `--var`, 目前只认 `基准日期` (值可以是 `"2026-10-23"`、`date`、`datetime`、`pd.Timestamp`), 覆盖「设置」里的值, 只作用于真实数据。

| `RunResult` 字段 | 内容 |
|---|---|
| `ruleset` | 加载后的 `RuleSet` |
| `tests` | 每条内嵌用例的 `TestOutcome` (`name` / `passed` / `hit` / `problems` / `error`); `tests_passed` 属性是通过数 |
| `stopped_by_tests` | 为 True 时因测试失败而停止, 以下字段为空 |
| `keys` | 主表上标识一行的列 (第一个参照表的匹配键; 没有参照表就是第一列), 控制台变更表用它 |
| `inputs` | `{输入名: (实际读的文件, 行数)}` |
| `out` | 完整结果表 (主表副本 + 两列审计; 有 `独有行: 追加` 时含追加的行)。输出列里的空值统一是 `None` (0.7 起不再 NaN / None 混用); 写出的 xlsx 里空值就是空格子 (openpyxl 读到 None, pandas 默认读到 NaN, `keep_default_na=False` 读到空串) |
| `changed` | `out` 中变更明细非空的行 |
| `written` | 实际写出的路径; `dry_run` 时为 None |
| `notes` | 运行提示, 如某个参照表重复键按「取第一条」处理 |

**分步调用** (消费方要自己读表、或把规则嵌进别的流程时): 包顶层还导出 `load_excel_rules` / `load_yaml_rules`、`build_namespace`、`apply_rules` 和 `Rule` / `RuleSet` / `TestCase` / `RunResult` / `TestOutcome`; `rule_sheet.engine` 里的 `read_table`、`add_derived`、`primary_frame` 是 `run()` 内部各步, 也可直接用。顺序与 `run()` 一致:

```python
from rule_sheet import load_rules, build_namespace, apply_rules
from rule_sheet.engine import read_table, add_derived, primary_frame, ns_index

rs = load_rules("rules.yaml")
tables = {"本期": read_table("本期.xlsx"), "上期": read_table("上期.xlsx")}   # 输入名 -> 表
ns = build_namespace(rs, tables, variables={"基准日期": "2026-10-23"})   # 以主表为锚 left join; 聚合 / 追加独有行都在这一步; variables 可省
add_derived(rs, ns, ns_index(ns), lenient=False)
originals = {c: ns[f"本期.{c}"] for c in rs.outputs if f"本期.{c}" in ns}
results, hits = apply_rules(rs, ns, originals)   # 每个输出列的新值, 每行的命中规则串
out = primary_frame(rs, ns, list(tables["本期"].columns)).assign(**results)   # 可能被「独有行: 追加」扩展过的主表
```

这些函数只加可选参数、不改已有签名。

## 9. 常见报错

| 现象 | 原因与处理 |
|---|---|
| `规则文件不存在: ...` | 路径写错 |
| `规则文件缺少输入表: 「设置」sheet里要有一行写列名 名称 / 匹配 ...` / `缺少「决策表」sheet` | sheet 名必须完全一致; 输入表从写着 `名称` 和 `匹配` 的那一行开始 (两个列名都要有)。旧的「输入」sheet / 「匹配设置」也认, 旧版式报错的前缀是 `「输入」sheet` |
| `「设置」sheet 里已经有输入表, 又有「输入」sheet` | 0.8 起输入表在「设置」里, 删掉旧的「输入」sheet (两处都有时不猜听谁的) |
| `「设置」sheet的输入表: 必须恰有一个输入的「匹配」写 主表 ...` | 主表那一行的「匹配」写 `主表`, 其它输入写键; 只有一个输入时可留空 |
| `「设置」sheet的输入表: 没有声明任何输入` / `输入名「X」重复` (YAML 的前缀是 `YAML 输入:`) | 输入表列名行之后至少一行; 两个输入不能同名 |
| `「设置」sheet的输入表: 输入「X」没有写「匹配」` | 参照表必须写对齐到主表的键 |
| `「设置」sheet的输入表: 输入「X」的匹配键「...」只能对齐到主表「...」` | 键右侧只能写主表的列 (星型), 不能对齐到别的参照表 |
| `「输入」sheet 第 1 行缺少「名称」列` (旧版式) | 旧「输入」sheet 的第 1 行是列名, 要有 名称 / 匹配 (重复键 / 独有行 / 排序 / 分隔符 / 空值占位 / 带序号 / 文件 / 说明 可选) |
| `YAML 输入「X」里的「Y」不认识, 只认: ...` / `YAML 里 输入: 和旧写法 匹配: 不能同时出现` | 输入声明的键只认 文件 / 匹配 / 筛选 / 重复键 / 独有行 / 排序 / 分隔符 / 空值占位 / 带序号 / 说明; 新写法 `输入:` 与旧写法 `匹配:` 二选一 |
| `YAML 顶层 / 第 N 条规则 / 第 N 条测试用例 里的「X」不认识, 只认: ...` | 键拼错了 (`命中测略` / `ID` / `期待`)。顶层只认 输入 / 匹配 / 设置 / 变量 / 字段组 / 命中策略 / 拼接分隔符 / 规则 / 测试; 规则只认 编号 / 名称 / 优先级 / 当 / 则 / 分支; 用例只认 用例 / 输入 / 期望。注释用 `#`。0.7.1 以前这些键会被静默忽略 (策略回落到 优先级、用例期望为空而假通过) |
| `「设置」sheet: 设置项「X」不认识` | 只认 基准日期 / 输出 |
| `「设置」sheet: 「拼接分隔符」写在决策表左上角「命中策略」下面一行` | 0.8 起分隔符和命中策略写在一起 (YAML 写在顶层); 旧版式 (单独的「输入」sheet) 的「设置」里写它仍认 |
| `「拼接分隔符」写了两处 (决策表左上角 和「设置」)` / `(YAML 顶层 和「设置」)` | 删掉旧位置 (「设置」/ YAML `设置:`) 里的那个 |
| `设置了「拼接分隔符」, 但命中策略是「优先级」而不是 多条拼接` | 策略名没写或写错 |
| `规则 G1 输出「标签」= 清空: 命中策略 多条拼接 只拼接有值的输出, 不能写 清空` | `多条拼接` 下清空没有意义, 想清掉这一列换别的策略 |
| `输入「X」「Y」没有绑定文件` | 规则文件里没写默认文件, 命令行也没给 `-i X=路径` |
| `命令行给的输入「X」不是规则声明的输入` | `-i` 的名称要和输入表里的一致 |
| `-i 要写成 名称=路径, 收到的是 '...'` | 命令行 `-i` 的格式是 `名称=路径`, 等号两边不要空格 |
| `运行时变量「X」不认识, 只认: 基准日期` / `--var 要写成 名称=值, 收到的是 '...'` | `--var` / `variables=` 目前只能给 `基准日期`; 名字拼错不会静默忽略。其它名字暂不支持 (要先在规则文件里有带默认值的声明, 见设计架构 5.12) |
| `基准日期「X」(运行时给定) 不是日期` / `(规则文件「设置」) 不是日期` | 写成 `2026-10-23` 这样; 给了空值也报这个 |
| `数据表不存在: ...` / `数据表 ... 里没有 sheet「X」, 有: ...` | 检查 `-i` 路径、规则里的默认文件与 `--base-dir`; `#` 后的 sheet 名要存在 |
| `主表「A」没有列「k」, 而输入「B」要按它对齐` / `输入「B」没有匹配键列「k」` | 匹配键列在两张表里都得有 |
| `输入「B」有 N 行重复键, 而它的「重复键」设置为 报错` / `「设置」sheet的输入表: 输入「B」的「重复键」只认 取第一条 / 报错 / 拼接` | 参照表一对多; 设为 `取第一条`、`拼接` 或先去重; 策略名拼错也在这里报 |
| `「设置」sheet的输入表: 输入「B」写了「排序」, 但「重复键」是 取第一条 而不是 拼接` / `主表「A」不能写「排序」` | 排序 / 分隔符 / 空值占位 / 带序号 只对 `重复键: 拼接` 的参照表有意义 |
