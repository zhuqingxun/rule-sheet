# rule-sheet

把「两份 Excel 互相比较, 按规则更新字段」这类逻辑, 从代码里抽出来变成非编码人员能读、能改的规则文件, 由一个小解释器执行。

规则可以写成 **Excel 决策表** (给业务人员) 或 **YAML** (给工程侧), 两者由同一个解释器运行, 语义一致。
思路对标 DMN 决策表 (Camunda / Drools / GoRules), 简化为 Excel 原生布局 + 中文关键词。

## 安装与运行

需要 [uv](https://docs.astral.sh/uv/)。

```powershell
uv sync
uv run rule-sheet run  examples/customer-sync/规则_决策表.xlsx   # Excel 决策表
uv run rule-sheet run  examples/customer-sync/rules.yaml         # 同一组规则的 YAML 版, 结果一致
uv run rule-sheet test examples/customer-sync/rules.yaml         # 只跑规则文件内嵌的测试用例
uv run pytest                                                    # 项目测试套件
```

`rule-sheet run` 先跑规则文件内嵌的测试用例, 全部通过才处理真实数据。选项:

| 选项 | 作用 |
|---|---|
| `--output PATH` | 覆盖规则文件里的输出路径 |
| `--base-dir DIR` | 规则文件内相对路径的基准目录, 默认规则文件所在目录 |
| `--ignore-tests` | 内嵌测试有失败也继续 |
| `--dry-run` | 只打印, 不写文件 |

输出文件是左表的副本, 多出两列:

| 列 | 内容 |
|---|---|
| 命中规则 | 这一行命中了哪几条, 按优先级排, 如 `R1; R3` |
| 变更明细 | 每个被改的字段: 旧值 -> 新值 |

原始数据文件不动。目标文件被 Excel 打开时自动换 `_v2` 后缀。

数据类型按 Excel 里的单元格类型走: 设为文本格式的数字串 (电话、带前导零的编号) 按文本处理, 不会被转成数字; 数值列、日期列正常识别。

## 先看哪个文件

样例在 `examples/customer-sync/`, 一个文件夹就是一个任务: 两份数据 + 规则文件放一起。

1. `规则_决策表.xlsx` 的「决策表」sheet。推荐给业务人员改的形态: 每行一条规则, 蓝色格是条件, 绿色格是命中后写回的值, `-` 表示不关心 / 不改。
2. 同一个文件的「测试」sheet。每行一个用例, 期望列留空表示「不变」。
3. `rules.yaml`。同一组规则的 YAML 写法, 条件是完整表达式, 支持 `任一满足` 嵌套。
4. `客户同步.feature`。Gherkin 写法, 只做验收说明书, 未接执行器。
5. `make_samples.py`。重新生成样例数据和决策表 (改了样例设计时才需要)。

## 样例数据设计

`客户主表.xlsx` 8 行, 每行对应一种情形:

| 客户 | 情形 | 预期 |
|---|---|---|
| C001 | 本月金额偏差 8% | R1 复核 |
| C002 | 偏差 3%, 普通客户 | 不动 |
| C003 | 本月缺失, 232 天未活跃 | R2 转休眠 |
| C004 | 本月缺失, 34 天 | 不动 |
| C005 | 试用客户偏差 30%, 电话变了 | 只命中 R3 换电话 |
| C006 | 偏差 8.3% 且电话变了 | R1 + R3 同时命中, 备注听 R1 |
| C007 | 已休眠 | 不动, 靠 `!= 休眠` 排除 |
| C008 | 金卡 4%, 本月电话为空 | R4 + R5a, 电话空不算变更但触发缺失提醒 |

## 规则文件结构 (Excel 版)

| sheet | 谁改 | 内容 |
|---|---|---|
| 匹配设置 | 工程侧, 一次性 | 左右表路径、别名、匹配键、一对多处理、基准日期、输出路径 |
| 变量定义 | 工程侧, 偶尔 | 派生变量, 如 `偏差率 = abs(本月.金额 - 主表.金额) / 主表.金额` |
| 决策表 | 业务侧, 经常 | 规则本体 |
| 测试 | 业务侧, 加规则时一起加 | 规则级单元测试 |

这个分层是 DMN 的核心思想: 复杂表达式写一次放「变量定义」, 决策表单元格里只允许少数几种形态。

## 单元格语法速查

| 写法 | 含义 |
|---|---|
| `-` 或留空 | 不关心 (输入) / 不改 (输出) |
| `活跃` | 等于 |
| `> 0.05` `>= 180` `!= 休眠` | 比较 |
| `!= 主表.电话` | 与另一个变量比较 |
| `[0.02..0.05]` | 闭区间, `(` `)` 为开区间 |
| `VIP, 金卡` | 枚举, 任一满足 |
| `"VIP 小幅偏差, 关注"` | 值本身含逗号时加引号, 否则会被当成枚举拆开 |
| `非空` `为空` | 判空 |
| `not(...)` | 取反, 只对有值的格成立 |
| 输出格 `本月.电话` | 复制该变量的值 |
| 输出格 `=表达式` | 公式计算 |

空值参与任何比较都不成立。要判空, 显式写 `为空` / `非空`。

## 条件之间的 AND / OR

| | AND | OR |
|---|---|---|
| Excel 决策表 | 同一行的各输入格 | 同一变量: 格内逗号枚举 `VIP, 金卡`; 跨变量: 拆成多行 (R5a / R5b) |
| YAML | `当:` 下的列表默认全部满足 | `任一满足:` 子列表, 可与 `全部满足:` / `不满足:` 互相嵌套 (R5) |

决策表故意不提供跨变量的 OR, 这是 DMN 的设计取舍: 每行一条「原子规则」, 多了一行就多了一条可以单独测试、单独追溯命中的规则。代价是行数变多。YAML 的嵌套更紧凑, 代价是缩进层级一多, 非编码人员容易看错括号归属。

还有一个容易忽略的差异: 决策表单元格里的比较 (`!= 主表.电话`) 由解释器保证空值安全, 任一侧为空就不成立; YAML 里的表达式是完整的程序语义, `本月.电话 != 主表.电话` 在主表电话为空时为真, 需要自己加一行 `非空(主表.电话)`。样例的 R3 两边都写了, 测试用例 T8 就是为了抓这个差异。

## 命中策略

决策表左上角 (YAML 里是顶层 `命中策略:`)。多条规则同时命中一行时:

- `优先级`: 每个输出列取优先级数字最小的那条。C006 同时命中 R1 和 R3, 电话来自 R3, 备注来自 R1。
- `唯一`: 任何行命中多条就报错停下, 并指出是哪个客户命中了哪几条。适合规则本应互斥的场景, 能在加新规则时立刻暴露重叠。

## 项目结构

```
src/rule_sheet/
  model.py        数据结构 (Rule / TestCase / RuleSet) 与关键词常量
  expressions.py  表达式求值 (中文变量名替换 + 受限 eval)、字面量解析
  conditions.py   单元格一元测试、YAML 条件组合、输出格解析
  loaders.py      Excel 决策表 / YAML 两种前端 -> RuleSet
  engine.py       合并两表、派生变量、命中策略合并、审计列、内嵌测试、写出
  cli.py          rule-sheet 命令
examples/customer-sync/   自带样例 (数据 + 三种写法的规则)
tests/                    pytest 套件
```

Python API:

```python
from rule_sheet import run

res = run("examples/customer-sync/rules.yaml", dry_run=True)
print(res.changed[["客户编号", "命中规则", "变更明细"]])
```

## 局限与候选 roadmap

- 表达式走 Python `eval`, 规则文件视为可信输入; 多人维护时需换受限求值器
- 一对多匹配只支持「取第一条」
- 没有静态校验: 重叠规则、永远不命中的规则、没覆盖的输入组合
- Gherkin 无执行器

规则数量上百或多人协作时, 也可以考虑 pyDMNrules (Excel 决策表 + pandas) 或 GoRules zen-engine (JSON + 可视化编辑器)。
